### CODE-006 · 独立生图模型 API 第一阶段完成

- 新增与聊天 `ModelRouteRegistry` 完全分离的 `ImageRouteRegistry` v1。连接名称/ID、模型、启用状态与能力进入版本化公开目录；`routeRef` 由服务端盐值对 connection/baseUrl/Key/model 身份生成不透明 HMAC，Key 和 baseUrl 仅存在运行时内存。目录、Session、AgentRun、事件、快照和错误均只保留非秘密身份；凭据变更会产生新 routeRef/revision，服务重启后未重新绑定凭据时稳定进入可恢复的凭据等待，不借用聊天 Key、workbar 路由或聊天模型。
- 服务端新增唯一 `generate_image` 工具和独立 `image_generation` 副作用。`read`/`plan` 不获得该工具，`accept` 复用可恢复授权门禁且仅显示模型、数量、尺寸、质量、格式和是否有参考图，不显示 prompt/Key/baseUrl；`bypass` 仍经过全部服务端限制。模型参数只允许 prompt、当前 Session 附件/生成资产身份、尺寸、质量、数量和格式；额外路由、header、Key 或本地路径字段在持久化前被脱敏拒绝。AgentRun 只冻结公开 image route 身份，背景 Child/队列未显式传入时不继承或猜测路由。
- 上游基础协议限定为 OpenAI-compatible `POST /v1/images/generations` 与单参考图 multipart `POST /v1/images/edits`，固定请求 `b64_json` 并发送确定性 `Idempotency-Key`。URL 回退仅在服务端内部使用：限定 HTTP(S) 默认端口、公网 DNS 全量校验与连接 IP 绑定、TLS 主机名验证、最多 3 次重定向、禁止 HTTPS 降级，并共享唯一总超时。URL/查询、Authorization、base64 和供应商域名均不进入工具结果、客户端、模型上下文或诊断。
- 生成图像限定 PNG/JPEG/WebP、每张 20 MiB、每批 1–4 张、每张 40 MP，以真实 signature、HTTP MIME、Pillow verify/decode、尺寸、响应总量和损坏校验 fail-closed。资产保存于单机 `code/data/generated-assets` 专用仓库，仅用高熵 asset ID 和 Session-scoped 受控 URL；旁车仅保留 session/run/tool call、hash、MIME、像素、字节和创建时间，不暴露服务器绝对路径。读取复核 Session 所有权和文件完整性，删除 Session 仅联动删除该 Session 资产。本阶段明确不支持多实例或对象存储。
- 外部请求前先持久化 operationId 与 `prepared`，在付费请求前原子切到 `dispatched`。已持久资产按 operation/session/run/call/count 确定性复用；重启发现 `dispatched` 但无完整资产时固定转为 `image_outcome_unknown` + `notReplayed`，不再自动请求上游，部分资产证据也不删除。拒绝、取消、超时、网络失败、401/403、429、无凭据、陈旧/禁用路由、非法响应与未知诊断均使用稳定且不含秘密的错误码。

## 2026-08-28 02:00 · Codex

### CODE-014 · Skill 执行证据校验正式完成

- observer v1 以服务端事实为唯一权威：AgentRun 创建时冻结该请求系统提示实际注入的 Skill 集合、每项 `SKILL.md` 内容哈希及经校验的可选 `evidence.json` v1 合同。显式 Skill 为单项，自动匹配沿用既有确定性排名、禁用排除和最多三项，不在恢复时重新匹配；客户端只能提交名称意图，不能提交合同或扩张 `allowedTools`。
- 观察结论只统计唯一的权威 execution/result 与成功产物事实，模型正文、自述、重复事件、原始命令、文件内容和 stdout/stderr 均不能证明成功，也不会进入快照或诊断。`satisfied`、`partial`、`failed`、`unsupported_completion`、`legacy_unverified` 五态保持 observer-only；旧 v5、单 Skill 旧形状及无合同 Skill 无迁移兼容读取。
- 第二阶段只为用户显式激活 `/code-review` 且冻结合同明确 opt-in 的运行启用低风险门禁，最低证据为一次成功且唯一的 `read_file`。自动匹配 `code-review`、其他 Skill、无合同/无效合同与旧记录继续 observer-only，门禁不改变工具权限、授权策略或执行顺序。
- 证据不足时，候选回答和脱敏缺口原子持久化为 `waiting_skill_evidence`。Continue 在同一 AgentRun 恢复并复用既有 execution，已完成工具不重放；Skip 不发模型请求，直接完成并记录 `userOverride` 与未验证状态；Cancel 复用既有取消终态。三种动作使用持久幂等身份，刷新、快速切换和服务重启后可恢复；关闭 `code-review` enforcement 后，新运行立即回到 observer-only，既有等待运行仍可 Skip 或 Cancel。
- `loadSession()` 在既有导航序列守卫内恢复完整 `skillEvidenceRequest`，只有当前会话渲染三按钮面板；非当前会话只显示侧栏状态。紧凑 Session 索引/API 新增可回退的 `interactionState`，值仅能是 `waiting_user_input`、`waiting_authorization`、`waiting_skill_evidence` 或空，由服务端从权威 pending request 推导；旧索引在现有加法回填锁内一次性补齐，metadata-only 写入保持已有值，完成、跳过或取消后清空。列表不暴露 request、gate、AgentRun、Skill、路径、命令、URL、凭据或错误正文，完整面板仍必须显式加载 Session，不能由摘要伪造。
