### Harness H4-2 真实刷新恢复补充修正与人工验收

- H4-2 原隔离浏览器回归已证明 Runtime 快照/游标追赶，但真实 Code Dev 人工验收仍可复现两条历史问题：首个正文增量前刷新或已有部分正文后刷新，页面会恢复运行状态与累计计时，但正文要等到终态才一次性出现；刷新后暂停也会因重附着过晚而错过实时窗口。不刷新的对照任务流式正常，排除了上游本身不流式。
- 真实页面时间线将根因定位为启动顺序：Session 恢复后仍等待 9 次串行 `/proxy/models` 模型目录请求，目录阶段约从 1.56 秒持续到 20.48 秒，首个 AgentRun GET 约在 20.61 秒才出现，此前没有 Runtime GET。`app.js` 现在保持 `platformSyncPromise` 和 `authExpired` 检查不变，但在 `refreshModels()` 之前立即调用既有 `sessionStartup.startRecovery()`，避免活动 AgentRun/Runtime 被模型目录阻塞。
- H4 隔离上游增加有界模型目录闸门与 arm/reached/released 时间线。三条 bundle 刷新场景都要求目录闸门仍阻塞时已产生新 Runtime GET：首增量前能恢复流式正文，两段后能恢复原前缀并在 terminal 前追加，取消能发出唯一 DELETE。本轮标准 H4 结果为 infra 通过、`6 passed`、零 retry；三例 Runtime GET 分别为 7/6/4，每例 AgentRun POST 1、Runtime POST 0、上游 chat 1，取消延迟 121 ms，不存在第二 Run、Runtime、assistant 或模型请求。
