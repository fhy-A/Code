#### 唯一写者协议

- 新增 tracked CLI `scripts/workspace_owner_lease.py`，作为 Codex/DSH 在同一物理 worktree 上唯一共用的写入租约实现；通过 `git rev-parse --absolute-git-dir` 将活动 lease、mutation lock 和最多 8 条 reclaim 前任摘要保存在 worktree 专属 Git-dir，不进入工作树、Git status、提交或业务数据，也不依赖 Codex task API / DSH mailbox。
- `workbar-owner-lease/v1` schema 只绑定 runtime、approval/developer 身份、stage、base HEAD、relayId、leaseId、UTC acquire/renew/expire 时间和 TTL。默认 TTL 为 900 秒，范围 60～3600 秒，5 秒时钟宽限内仍视为 active；lease 不保存 token、凭据、项目内容或不必要绝对路径，也不授予 push/tag/release/delete/线上配置权限。
- canonical `docs/approval-relay-protocol.md` 已把 DSH 用户确认的切换差量收口为唯一 CLI、schema、状态/退出码、Codex/DSH 使用顺序、切换/恢复和失败处理；根与 code 两级 `AGENTS.md` / `CLAUDE.md` 使用同一轻量引用规则，不复制第二套格式或重型实现说明。

#### 原子竞争与恢复

- 修改命令以 Windows `msvcrt.locking` / POSIX `flock` 竞争同一排他锁，并以同目录临时文件、`fsync`、`os.replace` 发布完整状态；空闲并发 acquire 只允许一个进程成功，同 holder 重试保留 leaseId 并续租，异 holder、错误 release/renew 立即拒绝。`status` 不创建或取得 mutation lock，保持零写入。
- 普通 acquire 不覆盖过期状态。显式 reclaim 必须在锁内确认旧 lease 完整且越过时钟宽限、expected leaseId 匹配、cached 为空、当前 HEAD 等于旧 base HEAD；HEAD/cached 漂移、损坏/未知 schema、历史损坏或残留 `.tmp-*` 初始化中断均 fail-closed，不提供 force 或静默清理。
- helper 尚不存在前的首次文件创建是本阶段唯一 bootstrap 例外；helper 可运行后，Codex 以当前审批/开发身份实际 acquire 并 renew，同一 lease 保护后续写入、验证与提交，提交完成后以匹配 holder/leaseId release，最终不留活动 lease。`CODE-033` 未启动。
