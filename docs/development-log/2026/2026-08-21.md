### CODE-012 · D-lite 实际上下文上限自动校准完成

#### 严格归因与本地校准事实层

- 新增 `code-context-calibration/v1` 本地事实层，作用域精确绑定规范化 Base URL 的 connection ID、实际请求 Key 的不可逆 SHA-256 指纹和 canonical model；原始 Key、Authorization、Base URL 原文、请求内容及上游错误正文均不进入校准文件、Agent 公开事件或前端。校准文件位于 `DATA_DIR/context-calibrations.json`，以跨进程文件锁、锁内重新读取合并、临时文件 `fsync + replace`、确定性 observation ID、每 scope 有界 observations 和未过期最小 cap 保证并发与幂等。
- 严格学习分类器与既有宽泛恢复分类分离：只有 HTTP 400/413/422 且命中明确 context code/短语才会停止当前 Key fallback；429、超时、5xx、权限/模型不可用、内容审核及模糊“too many tokens”继续原行为且不学习。显式最大值只接受结构化白名单字段或与 maximum context length/window 紧邻的 1,024～2M 整数；冲突数字、requested-token、年份和 request ID 不会被误取。
- explicit maximum 成功证据保留 30 天，heuristic 阶梯成功证据保留 7 天；同 scope 多证据取有效最小值。未知 schema、损坏或中断不会覆盖/修复原文件：读取侧禁用校准并允许普通未校准请求继续，学习写入以 `storage_unavailable` fail-closed；测试、构建和 H4 均使用临时 `DATA_DIR`，收口时真实项目 `data/context-calibrations.json` 不存在。

#### 单次同 Key 恢复、事务与兼容

- 明确 context 错误在 Model Runtime 实际 attempt 处锁定失败 Key；候选优先采用严格提取且低于当前最终限制的 explicit maximum，否则按 `2M / 1.05M / 1M / 400K / 256K / 200K / 128K / 64K / 32K / 16K` 取下一较低档，并先核对 Max Tokens、5%/4K 安全余量和最低 1,024 输入空间。当前 AgentRun 同一 round 只允许一次 D-lite 恢复，压缩与模型重试都只使用失败 Key，其他 Key 不会被请求。
- sanitized pending calibration 在重试前持久化，刷新/重启后必须从用户重新提供的 Key 列表按指纹匹配；缺失时回到 `waiting_credentials`。压缩失败、重试失败、取消或异常会恢复当前 Run 原 contextLimit，且不写成功记录；重试成功后必须先原子 `record_success` 并持久化 Run 降低后的快照，才接受 assistant 内容或 tool calls，store 失败会丢弃模型结果并保持工具/写操作零执行。
- 成功校准按 `min(能力层或允许的 soft 尝试、校准 cap、用户预算)` 进入唯一 resolver；`contextWindowTokens/source/hard` 继续描述 metadata/official/family 能力，不把校准伪装为 metadata。当前 Run 单调降低并重算 available input/压缩阈值，后续同 Key+连接+模型的新 Run 读取有效 cap；其他 scope 完全隔离。旧 Run 无新增字段时保持 legacy 且不迁移，Child、Goal successor 继承成功后的父快照，queue/background 在创建时由服务端按首选 Key 解析，完成的前台 Run 将同一安全事实写入既有 Session stats 可选字段。
- 前端只显示双语短提示“该连接实际窗口较小，已自动调整为 X”，以 `sessionStorage` 对同一 Run+cap 去重，刷新不重复；公开事件类型和 Agent protocol v1 未改变。R027 进一步把 AgentRun 创建时间改为进程内单调微秒精度，消除同秒随机 runId 误判新旧而拒绝 64K Session 事实的竞态；R029 冻结 follow-up 点击时的目标 AgentRun ID，关闭保存消息期间活动上下文清理造成“已投影但既未 steer 也未入队”的竞态，终态 Run 仍按既有 409→queue 路径处理。
