### AgentRun 自动上下文压缩与任务中途续行

- 前端在创建前台及后台 AgentRun 时按模型族传递 `contextLimit`；服务端对旧客户端和旧持久记录保留相同的模型族默认值，并在每次模型请求前估算包含消息、工具定义与请求选项的完整上下文。默认达到上下文上限的 90% 时触发压缩，中文与其他非 ASCII 文本使用保守估算，避免只按英文字符比例低估。
- 自动压缩保留所有系统消息、当前真实用户任务原文，以及当前任务内最近一组完整的 assistant 工具调用和对应 tool 结果；其余较早过程交给同一模型生成检查点摘要。压缩请求不计入 Agent 模型轮次，但 usage 会并入任务累计用量；成功后在同一 AgentRun、同一任务中继续下一次模型请求。
- 上游实际返回 `context_window_exceeded`、`maximum context length` 等上下文错误时，同一模型轮次最多执行一次响应式压缩与重试，第二次仍超限则保留原错误终止，避免无限循环。压缩失败不会替换原始消息；取消任务时会通过现有活动 runtime 取消链路停止压缩请求。
- AgentRun 持久记录以向后兼容的新增字段保存 `contextLimit`、压缩记录和响应式恢复轮次；旧 version 2 记录无需迁移即可恢复。压缩开始、完成和失败均写入持久事件流；前端按事件原位显示“正在自动压缩上下文…”并在完成后更新为“上下文已自动压缩”，该记录与阶段说明和工具组保持时序，最终回答出现后一起收进“已处理”执行轨迹。
- 自动压缩不弹确认框；手动 `/compact` 继续保留确认流程与最近 3 个完整用户轮次，同时修复消息替换后未显式 `persistMessages: true` 的持久化缺口。上下文用量提示已从未实现的 95% 文案改为实际的 90%。会话 JSONL、工具协议和既有手动压缩 API 均未做破坏性修改。
- 自动验证通过：`python -m pytest tests -q -p no:cacheprovider` 共 881 项及 236 个子测试通过；Agent 运行时、前端模块与 P0 定向阶段回归均通过；Python/JavaScript 语法检查和目标文件 `git diff --check` 通过。`server.py` 仍报告既有的 `invalid escape sequence '\\C'` SyntaxWarning，本批未扩大范围处理。按用户约定未操作浏览器或系统界面，真实页面视觉验收留待用户手动重启 Code 后确认。
