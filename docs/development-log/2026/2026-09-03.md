- 根因闭合为活动 server AgentRun 与 Session CAS 的恢复控制流缺口：一次 revision conflict 会退役产生陈旧写入的精确 messages 数组并应用服务端权威 Session，但旧运行上下文仍可能持有该数组继续消费事件；此前后续保存会在 PUT 前静默短路，事件 cursor 又可能先于消息持久化推进，最终 terminal clear 还能基于旧权威状态清空 runState，导致问卷结果、后续工具或最终回答只留在 AgentRun 而未写回 Session。历史故障的实际竞争写者与精确触发时刻仍为 unknown；跨页 / 跨 tab 与 late `beforeunload` 仅是未证实候选，不写成历史结论。
- 前端现将 CAS 冲突显式纳入活动投影恢复：任何 filter / clone 前先保留退役数组身份，只接受同 sessionId、同 agentRunId 且仍由 `server-agent` 持有的权威 Session，以其 messages、stats、runState 与 durable cursor 重绑上下文并重放；同一 cursor 最多恢复 3 次，第 4 次转为可恢复失败。每个 Agent 事件先携候选 cursor 保存消息与 checkpoint，确认持久化成功后才提交内存 cursor；不关闭 CAS、不合并任意 stale 本地消息，也不重放服务端工具副作用。terminal clear 在网络失败时恢复原活动 runState，CAS 冲突时保留权威 checkpoint，只有确认保存成功才留下空 runState。
