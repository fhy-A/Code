### CODE-046 · 首条消息即时反馈与连接中心 Route Registry（用户 H4 组合 PASS）

#### 完成内容

- 将新任务发送拆为可恢复的唯一意图：用户提交后先在当前 Session 持久化并展示唯一用户消息和待发送状态，再异步完成可信路由。路由成功只创建一个 AgentRun；失败保留原消息与可操作错误，重试复用原消息而不重复 AgentRun。Session revision/CAS、权威恢复顺序和共享终态 ownership 发布共同阻止跨页面迟到写、恢复误报与完成后下一条消息误分流。
- 路由事实收敛到服务端连接中心 Route Registry：稳定非秘密 `connectionId + modelId` 由服务端生成不透明 `routeRef`，目录按现有连接名称展示该连接实际支持的模型；同名模型可属于不同连接，但不得跨连接回退。公开目录、Session 和新 AgentRun 只保存 `routeRef`、`catalogRevision`、`modelId` 等非秘密身份，Key、Authorization 与内部 baseUrl 仅存在于服务端运行期解析层。
- manual Key 与 workbar Token 均通过现有连接配置自动探测模型；服务端逐后端隔离收集，部分后端失败时仍保留其他健康连接，全部失败才 fail-closed。前端目录刷新按连接快照与意图 singleflight，同一在途操作去重，配置变化或显式刷新最多排一个最新快照尾随刷新；已有有效 `routeRef` 和运行时凭据时直接派发，不等待后台目录刷新。
- `routing_v2` 新请求使用 `routeRef/catalogRevision` 且与 legacy `keys[]` 互斥；旧 v3 目录缓存仅作非权威展示，旧 modelId 仅在唯一匹配时无感升级，歧义进入显式路由选择。旧 AgentRun 与 legacy Key 字段继续只读兼容，不重写历史 JSONL；队列、后台、Child、手动压缩、标题和恢复路径统一继承或提交精确连接身份。
