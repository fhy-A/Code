# Code v0.6.6 Release Notes

日期：2026-08-29

<!-- code-release-notes:body:start -->
## 更新重点

- 新手首次使用路径收敛为欢迎页三步任务，并补齐最多五题的结构化问卷、终态恢复和连续问卷 exactly-once；自动模式在首次启用前明确展示风险并默认允许取消。
- 聊天模型改由连接中心的稳定路由身份精确绑定，首条消息可先保存和显示，再异步完成可信路由；删除、禁用连接或退出 workbar 后会立即撤销失效模型路由，不再跨连接猜测或复活旧绑定。
- AgentRun 支持在已有进展后的断网、流中断、超时和服务重启中恢复，同一运行继续复用已完成工具结果；固定轮次上限移除，上下文窗口设置改为表达用户期望的最大值，实际安全上限仍由服务端可信能力和校准决定。
- 独立生图能力完成从路由、授权、单图上游批次到一等图片输出、编辑和受控资产转存的闭环；多图按独立请求并发执行并保持稳定顺序，刷新和重启不会重放已经派发的付费请求。
- 会话归档升级为物理可恢复归档，设置页可恢复或永久删除；新增活动会话全局搜索与归档域内搜索，两类结果和动作严格隔离。
- Skill 执行证据 observer 与显式 `/code-review` 门禁正式可用；PPT Master 以独立显式 `/ppt-master` 离线试点接入，可从 Markdown/TXT 生成包含 CJK、文本、形状、表格和原生图表的可编辑 PPTX，同时保持默认 `/pptx` 完全不变。

## 新手任务、问卷与连接路由

- 登录后的欢迎页提供连接 workbar、确认可用 Key、选择模型并完成首次前台任务的三步引导；示例只填入输入框，不会自动发送。进度使用最小本地状态并兼容旧用户，新手入口不再占用设置页。
- `request_user_input` 统一支持 1–5 个问题；每题使用 2–3 个选项、允许自定义输入并给出唯一推荐及理由。五题按原顺序完整保存和恢复，六题稳定拒绝；文本、点击和 Enter 提交继续只恢复同一 AgentRun 一次。
- 已取消、失败或完成运行遗留的问卷会按权威 AgentRun 终态清理，健康问卷保留部分进度；刷新对账不会新增消息、工具执行或替代运行。前台 Agent 也可通过受控 Goal 取消工具结束 draft、active 或等待中的 Goal，而不等同于中断当前传输。
- 连接中心以非秘密 `connectionId + modelId` 和服务端不透明 `routeRef` 绑定模型，同名模型可来自不同连接但不会跨连接回退。公开目录、Session 和 AgentRun 不保存 Key、Authorization 或内部 base URL。
- 首条消息先唯一保存并即时显示，再异步解析可信路由；失败时保留原消息并允许安全重试，不重复创建消息或 AgentRun。已有有效路由不等待后台目录刷新，部分连接探测失败不会影响其他健康连接。
- 删除或禁用聊天连接、删除 Key、退出 workbar 或权威空目录刷新会清除对应公开路由和运行时凭据；新消息、图片附件和排队入口只有在当前路由启用且凭据可用时才能派发。运行中的取消、已有恢复和旧 `routing_v1` 兼容路径保持原语义。
- 从非 Auto 权限档切换到 Auto 前会显示清晰的能力与风险确认；取消、关闭、Esc 或遮罩不会持久化 Auto，也不会创建 Session、消息、Goal 或 AgentRun。越界路径、危险命令、破坏性 Git 和服务端参数校验等硬限制没有放宽。

## AgentRun 恢复、上下文与工具协议

- 移除前端、服务端和 Goal 的固定轮次终止上限；首次模型调用仅在 120 秒内没有任何有效正文、推理或工具证据时硬中断。用户取消、权限、Skill、工具预算、重复失败和重复副作用保护继续生效。
- 已有进展后的断网、流中断、后续超时或服务重启会进入持久 `waiting_recovery`；恢复固定使用原 `routeRef`、同一 AgentRun 和模型检查点，已完成工具结果复用，未完成工具不会被误执行或自动重放。
- 自动压缩使用禁止工具调用的专用最终摘要；空摘要只立即重试一次，之后持久退避。只有非空、结构有效且确实缩小上下文的候选才替换历史，失败保留原消息并进入可恢复状态。
- “最大上下文窗口”保存用户期望值，不再因当前模型的软估算而改写；可信硬元数据和同连接、同模型校准仍可静默降低实际 `contextLimit`。显式 200K 等设置在切换模型、刷新目录和重载后保持。
- 并行视觉工具的 assistant 声明、全部 tool 回执和后续视觉结果按固定连续顺序持久化；旧记录只在请求内存投影中安全恢复，冲突或孤立证据在本地 fail-closed，已完成工具不重放。明确的工具协议错误独立显示，不再误导用户检查 Key 或模型权限。
- 最终回答中的本地文件、目录、图片和行号只有在给出完整绝对路径时才可点击；项目外目标在插入页面前降级为普通文本且零访问，相对路径仍可用于说明和工具参数，但不再按项目根猜测打开。

## 独立生图、编辑与资产管理

- 生图模型拥有独立于聊天模型的连接、默认模型和路由目录；`imagegen` Skill 与唯一 `generate_image` 工具使用单独的 `image_generation` 权限。公开状态只保留脱敏身份，Key、上游 URL、base64 和服务器缓存路径不会进入 Session、模型上下文或页面。
- 支持 OpenAI-compatible 文生图与当前 Session 单参考图编辑；编辑能力不再依赖手工开关，明确不支持的上游返回稳定错误且不自动重试。新模型工具只公开 prompt、受控 reference 和 count，尺寸、质量与输出格式由运行时统一管理。
- 用户明确要求 2–4 张时，运行时将一次工具调用拆成多个固定 `n=1` 的独立请求，并发上限为 2；每项拥有独立幂等身份，按请求顺序展示并允许部分成功。系统性失败、结果未知或用户取消会阻止尚未派发的项目。
- 所有付费请求在派发前持久化状态；刷新、服务重启或旧批次恢复会重新核对批次身份与资产完整性，未知结果固定为 `notReplayed`。同一 AgentRun 在非重试或结果未知后无法通过改变参数再次派发，新用户消息创建的新运行才可重新尝试。
- 生图共享总预算提升至 180 秒，并覆盖请求、响应读取、解码与受控 URL 回退；超时只声明送达和结果未知，不伪称上游已收到，也不会产生第二次派发。
- 成功图片以独立 gallery 显示在紧凑执行轨迹之后、最终回答之前；单图大图、多图网格、下载和大图查看保持 Session 所有权与刷新去重，工具详情不再重复嵌图。
- 新增受控图片转存：经 `file_mutation` 授权后可把当前 Session 的权威资产原子保存或重命名到项目 `output/generated-images`，并可在后续 Session 作为工作区参考图使用。路径穿越、符号链接、覆盖冲突、跨 Session 资产和内容篡改均拒绝；Child Agent 不继承生成或转存工具。
- 后续模型运行只获得 asset ID、MIME、像素、字节等有界历史身份，可继续编辑或经授权做本地处理，无需用户复制内部 ID，也不会暴露内部缓存位置。

## 会话归档、删除与双域搜索

- 会话归档使用独立物理 bundle，manifest 固定原 Session 路径、摘要、时间和状态令牌；journal 与 staging 覆盖归档、恢复和永久删除的崩溃窗口。双位置、篡改、损坏、越界路径或未知事务状态统一 fail-closed。
- 新写入进入带所有权标记的受管命名空间；早期无 manifest 的 root-level 备份不会被读取、移动、删除或误列为归档，有效旧版 bundle/journal/staging 继续兼容恢复。
- 活动会话菜单可直接归档；设置页按项目列出归档会话，支持恢复和带当前 token 的单条永久删除。归档态不能打开、回复或创建新 AgentRun；恢复不会产生模型、工具或聊天副作用。
- 无秘密派生索引只记录 Session 与 AgentRun 身份，用于判断归档资格和有界永久删除；索引缺失、构建中、损坏、陈旧或冲突时保守拒绝，不回退到扫描全部历史。删除成功会清理目标 core、Goal、生成资产和终态 AgentRun，不影响已保存到项目目录的文件。
- Logo 旁新增活动会话全局搜索：空查询显示跨项目最近 10 条，非空查询按标题、完整或部分 Session ID 匹配全部结果；状态只投影已有运行或空闲事实。设置页归档搜索只过滤已加载的归档记录，活动与归档结果不会混入彼此。
- Session 删除、归档和恢复的 HTTP/1.1 提前返回路径会先精确消费当前请求体，避免污染同一 keep-alive 连接的下一请求；Windows 文件锁、索引、Goal 或资产删除失败会回滚全部权威事实并返回脱敏错误，迟到保存和图片结果不能复活已删除 Session。

## Skill 证据与 PPT Master 离线试点

- AgentRun 在创建时冻结系统提示实际注入的 Skill 集合、每项 `SKILL.md` 哈希和可选 `evidence.json` 合同；显式与自动匹配使用同一请求快照，后台 Child 不继承父任务 Skill。合同只能引用当前运行已经允许的工具，客户端不能提交合同或借此扩权。
- Skill 证据只统计唯一权威 execution/result 和成功文件产物；模型自述、重复事件、命令正文、stdout/stderr 或文件内容不能冒充完成。无合同、旧记录或无效合同安全降级，不迁移旧 AgentRun。
- 显式 `/code-review` 可在证据不足时进入 `waiting_skill_evidence`：Continue 在同一 AgentRun 复用既有工具结果，Skip 零模型请求完成并记录用户覆盖，Cancel 使用既有取消终态；刷新、切会话和服务重启后仍可恢复。
- PPT Master 固定来源为上游 `hugohe3/ppt-master` `v5.1.0` 的精确 commit/tree，仅纳入经过哈希、Git blob、许可和静态能力校验的 66 个离线核心文件。自动更新、`.env`、网络/provider、图片下载、TTS、动画、旁白、视频、本地服务、模板/品牌/Icon/Sound 和 Image-to-PPTX 均未进入包。
- `skia-pathops==0.9.2` 与 `uharfbuzz==0.50.0` 使用官方 Windows wheel、精确哈希和受管 Python 安装 receipt；工具投影与每次执行前都会重验 lock、receipt、dist-info/RECORD 及其声明文件，任何缺失、额外文件或字节变化都会在 worker 启动前拒绝。
- `/ppt-master` 仅显式匹配，并通过结构化 `create_ppt_master_deck` 接受 inline UTF-8 Markdown 或项目内不超过 1 MiB 的 `.md`/`.txt`；输出固定为 `output/ppt-master/<AgentRunId>/presentation.pptx`，使用 run-owned staging 和原子发布，不允许任意脚本、命令、URL、输出目录、符号链接或覆盖旧文件。
- 首阶段支持离线 CJK、文本、形状、表格和原生图表，并纳入 `file_mutation` 授权、AgentRun 幂等恢复和 30 秒进程树取消。PPTX 发布会拒绝宏/VBA、OLE、ActiveX、音视频、custom XML 和未批准部件；原生图表所需的唯一受管 workbook 另行严格校验。
- Markdown 连续普通行按段落合并，段落与列表使用不重叠布局；首阶段不支持的表格/图表混排会明确拒绝，不会静默丢内容。默认 `/pptx`、其自动匹配、既有 Skill 文件和旧 PPTX 均保持不变。

## 安全、兼容与稳定性

- 新增开发环境 `doctor`，统一检查当前/H4 Python、必要模块、Node/npm、esbuild、Playwright 与受控 Chromium，并验证临时目录和进程清理；正式 release 门禁仍使用原有共享验证定义，H4 不进入发布 profile。
- 生图、聊天路由、Skill 证据和 PPT Master 均使用非秘密身份与稳定脱敏错误；真实 Key、Authorization、内部 base URL、缓存路径、模型私有推理和上游原始错误不会进入公开快照或诊断。
- 新增的 Session、AgentRun、路由、Skill evidence、归档和 PPT Master 字段均以可选或独立存储兼容旧记录；没有批量迁移或重写历史。损坏、冲突和恢复结果不确定时优先停止，不通过自动重试、跨连接回退或近似路径继续执行。
- Windows Explorer、外链 favicon 和前端既有文件/链接交互继续兼容；favicon 对 1×1 退化图、临时失败和并发队列增加安全恢复，浏览器仍只访问同源代理。
