# Code v0.6.12 Release Notes

日期：2026-09-12

<!-- code-release-notes:body:start -->
## 更新交接与启动诊断修复

- 修复应用内更新后新版本无法启动：恢复 v0.6.8 改写更新器时丢失的三条语义（有界等待同镜像进程退出、清理失败时不阻断启动、替换文件通过既有校验后无条件拉起新版本）。更新完成后新版本会正常启动，不再出现“点完之后毫无反应”。
- **陈旧交接收口**：上一次更新留下的、已被当前运行版本取代的 journal 会被**持久化收口为终态**，不再每次启动都弹出“更新未完成”的提示；只有当待恢复交接的版本**严格高于**当前运行版本时才提示一次。
- **区分“读不到”与“不合格”**：读取已下载的更新文件失败现在是**可重试**的独立错误（`download_verify_unreadable`），不再被误判为“不是有效的 Code 可执行文件”；校验摘要时遇到读取失败同样按读失败处理，不再向上抛出未分类异常，也不会被安装路径误记为“安装器无法启动”。
- **更新后旧版本 EXE 有界清理**：保留当前运行版本与上一个版本，删除更旧的 `Code-v*.exe`。清理只在**新版本已接管数据目录锁、服务就绪之后**由运行中的实例执行；**绝不删除正在运行的镜像**，被占用或删除失败的文件跳过并记录原因；清理失败不会影响启动。
- **启动失败可诊断性**：技能运行时启动失败时，对话框与旁路日志会写入底层错误的 `errno` / `winerror` / 文件名与原始消息，便于直接定位到具体路径与操作。**打包入口（launcher）路径同样透传**这些细节，保证安装版用户看到与开发版一致的诊断。
- **启动失败提示可操作**：提示会说明“可能有另一个 Code 实例仍在运行，或上一次退出不干净”，给出“退出其它 Code（托盘图标右键 → 退出）后重试，或重启计算机”，并在可枚举时列出正在运行的 `Code-v*.exe` 进程（PID 与可读路径）。Code **不会**为此终止、挂起或抢占任何进程，占用检查与单写者语义均保持不变。

- **修复较长 Windows 用户名下的技能库启动失败（路径超过 260 个字符）**：暂存区目录名不再沿用操作的完整 ID，改为「前缀 + 前 16 位」的短名，并在启动时把**旧版本留下的长名暂存目录就地改名**（改名失败只跳过，绝不影响启动）；临时文件命名也不再内嵌完整 ID，管理通道（安装 / 更新 / 卸载技能）同样改走短名。实测报告案例的完整路径由 **266 降到 218**，本仓库最长内置资源路径由 **290 降到 242**（在 15 字符用户名下都 ≤ 260，不再依赖系统长路径开关）。**升级兼容**：旧的 64 位 operation ID 与旧的暂存目录残留都不会导致升级后启动失败——已确认既有旧技能库（`transactions` 与 `staging` 目录名均为旧 64 位 ID）升级后能正常完成恢复。

## 已知限制

- 技能库启动失败的**其它成因**（权限、安全软件拦截、异常条目等）仍需用增强后的诊断输出（`underlying=… filename=…`）在具体机器上定位；本版修复的是已确认的“路径超过 260 个字符”这一成因。
- 本版本为本地候选产物，**尚未对外发布**。
- 从 v0.6.8 / v0.6.9 升级到本版的用户：这次更新由旧版本自带的更新器执行，无法自愈；下载与落盘正常，但更新完成后需要手动双击一次安装目录（用户主目录下的 .code）中已下载的新版 EXE 才能启动新版，之后快捷方式会自动指向新版本。
