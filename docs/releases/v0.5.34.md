# Code v0.5.34 Release Notes

日期：2026-08-12

<!-- code-release-notes:body:start -->
## 更新重点

- 完善运行中任务的页面刷新恢复：活动 AgentRun 会在模型目录刷新完成前优先重附着，已产生的流式正文可以追赶并继续追加，刷新后暂停仍作用于原任务，不创建第二个模型请求、Runtime 或助手回复。
- 新增 TIFF 的浏览器派生预览与页面生命周期缓存。发送前、发送后、放大和完整刷新均可恢复预览；原始 TIFF 仍是唯一持久化附件，派生 PNG 与 Blob URL 不写入会话或磁盘。
- 统一任务耗时展示：主任务与普通排队任务在对应用户消息后的完成状态中各显示一次耗时，detached `/parallel` 结果保留自己的页脚耗时，不再互相接管或重复显示；中英文界面分别使用“用时”和 `Worked for`。

## 刷新恢复与任务隔离

- 问卷等待态支持完整刷新恢复。单题及混合必答问卷会保留已确认进度，提交后只恢复一次原 AgentRun；问卷等待期间加入的单条队列消息会在主任务完成后按原顺序唯一提升。
- 编辑建议在等待授权时可通过完整刷新恢复原 proposal、diff 与选择。已验证的批准、拒绝、陈旧文件冲突及授权请求到达服务端前失败后的单次手动重试路径，不会重复恢复、应用、写入或备份。
- 加强 detached `/parallel` 与主任务的状态隔离和消息排序。后台失败或完成结果不再取得主任务工具轨迹与顶部耗时的所有权，主任务仍可正常完成并继续追问。
- 模型在 forced-final 阶段失败时会收敛为唯一、可持久化的错误消息和失败耗时；完整刷新不会重新执行既有模型或工具步骤。

## 兼容与安全边界

- 继续兼容既有会话 JSONL、AgentRun/Runtime 记录、工具协议、bundle 与 classic fallback，不需要迁移或重写历史会话。
- TIFF 预览接口只处理受限附件目录内的安全路径，并沿用格式、大小、像素和路径校验；预览失败会安全回退为附件卡片，不阻止原附件发送。
- 编辑授权仍以现有用户决定和陈旧内容保护为边界。本版本的验证不扩展为通用服务端幂等、任意外部副作用 exactly-once 或所有并发、崩溃和跨进程恢复场景。

## 发布与质量

- Harness 第一轮已在有限工程边界内完成，覆盖 replay、浏览器 bundle/classic 对等、流式刷新、工具生命周期、失败收敛、TIFF、耗时、问卷、编辑授权、队列及 detached `/parallel` 等固定场景。
- 最终自动化证据包括两轮各 `67 passed` 的 H4 Chromium 矩阵、完整 pytest `1126 passed, 751 subtests passed`，以及 replay `17 fixtures / 124 events / 25 checkpoints / 25 checkpoint recoveries / 4 explicit recoveries`；replay suite hash 为 `166a8141c50e8cf17748a04e2b6aa994323c563e9d8d22d3aa4f6d17682030c2`。
- 发布候选人工验收第 1～8 项均已通过，覆盖启动与普通对话、流式刷新、只读工具、问卷和编辑授权、`/parallel` 隔离、普通图片与 TIFF、耗时与中英文切换、完整重启恢复，以及真实 `bundle-load` classic fallback 普通对话。
- 正式发布流程新增独立 Harness replay 门禁，并在提交、标签和 GitHub Release 前阻止空正文或含占位文案的发布说明进入发布链。

## 当前边界

- 本版本不宣称 active worker 跨进程恢复、全部异构工具与失败组合、多标签页或多 actor、Firefox/WebKit、真实外网与凭据、性能 SLA、主观视觉和可访问性场景已经穷举。
- 后续 Harness 轮次和其他产品事项不属于 `0.5.34`，也不会由本次发布自动启动。
