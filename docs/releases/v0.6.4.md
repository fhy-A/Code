# Code v0.6.4 Release Notes

日期：2026-08-21

<!-- code-release-notes:body:start -->
## 更新重点

- 统一模型上下文窗口能力、用户工作预算和 AgentRun 最终限制：服务端成为唯一 resolver，可信模型 metadata、官方能力目录、模型族估算、用户预算、Max Tokens 与安全余量进入同一计算链，并兼容旧缓存、旧设置、旧 Session 和旧 AgentRun。
- 新增按实际 Key、连接和模型隔离的上下文上限自动向下校准：只有明确的 context-length 错误会触发同 Key 单次压缩重试，成功后才原子记录较低上限，失败或取消不会学习，也不会把一个 Key 的限制应用到另一个 Key。
- 增强文件树、用量统计和复杂 Goal 可靠性验证；同时加入跨运行时工作区 owner lease、approval-relay v2 协作协议，以及可验证、可恢复的 prepared 两阶段发布流程。

## 上下文能力、预算与自动压缩

- 服务端统一解析上下文能力，前端不再维护第二套模型族表。模型目录只接受白名单 metadata 和 1,024～2,000,000 的整数；同连接多 Key 候选在相同可信层取最小值，冲突或损坏数据安全回退且不会提高硬上限。
- 模型目录缓存继续读取 v1 字符串列表，live 刷新成功后写入包含安全能力 metadata 的 v2；刷新失败保留既有缓存，旧客户端传入的 `contextLimit` 只能向下收紧，不能伪造可信模型能力。
- 设置页将温度、最大输出和上下文预算收拢为两列加独占一行布局。上下文预算使用单输入框，支持留空/`auto`、整数与 K/M 后缀；无效输入恢复上次有效值，不覆盖存储。Max Tokens 跨设置重开和刷新保持，预算修正不会静默改动它。
- 新 AgentRun 冻结模型能力、用户预算和最终 `contextLimit`。输入预算扣除 Max Tokens 与 `max(4096, floor(contextLimit×5%))` 安全余量，压缩触发点取最终限制 90% 与可用输入预算的较小值；非法组合在发送前拒绝。
- 完成的前台 Run 将安全的上下文解析快照原子写入 Session stats；同 Run 重放幂等，较旧 Run 不覆盖较新事实。Child 与 Goal successor 继承父 Run 快照，queue/background 在创建时冻结，运行中设置变化不会改写历史 Run。
- 顶部上下文环图只显示整数百分比，展开 Token 面板显示“百分比 · 最终窗口”。自动压缩 checkpoint 继续保存在 AgentRun 内部消息和 compaction 记录中，但 live、刷新和完成恢复均不投影为普通 assistant 消息；对话只保留压缩状态行和唯一最终回答。

## 官方模型能力目录

- 新增随代码发布的 `code-official-model-capabilities/v1` 静态目录，基于官方一手资料核对 OpenAI、Anthropic、Google、xAI、DeepSeek、Kimi、Qwen 共 7 个 provider、37 个 canonical variant；31 项提供可审计数值，6 项资料不足的条目保留为无数值研究状态，不以猜测补齐。
- resolver 优先级为 live 可信 hard metadata → `official`/`stale_official` → family → unknown。官方目录始终是允许用户显式尝试突破的 soft estimate，不覆盖 live hard metadata；稳定条目过期后继续使用同一保守值，moving alias 超期停止匹配。
- 匹配仅使用小写化、既有 Google `models/` 清理和逐项精确 alias，不剥离 provider/vendor 前缀，也不使用宽泛正则。目录 schema、官方域名、范围、重复 ID 或跨 provider 冲突任一异常都会禁用整个官方层并安全回退。
- 修正多项模型族估算偏差：`gpt-5.4-mini` 与 `gpt-5.1/5.2/5.3-codex` 使用 400K soft estimate，`gpt-5.6` 使用 1.05M；`maxOutputTokens` 只用于可选提示，不跨网关硬钳制用户的 Max Tokens。

## 实际窗口自动向下校准

- 严格学习分类器只接受 HTTP 400/413/422 下明确的 context code 或短语。429、超时、5xx、权限/模型不可用、内容审核及模糊 token 错误继续既有 fallback 且不学习；显式最大值只从结构化白名单字段或 maximum context length/window 邻接数字提取，request ID、年份、requested-token 和冲突数字不会被误认。
- 校准 scope 精确绑定规范化连接、实际失败 Key 的不可逆 SHA-256 指纹和 canonical model。原始 Key、Authorization、Base URL 原文、请求内容及原始错误正文不会进入校准文件、Agent 公开事件或前端。
- 候选优先采用严格提取且低于当前限制的 explicit maximum，否则按固定保守阶梯选取下一较低档；候选还必须为最大输出、安全余量和最低输入空间留下合法预算。压缩和恢复请求仅使用实际失败 Key，同一 AgentRun 同一 round 最多恢复一次。
- `code-context-calibration/v1` 使用跨进程文件锁、锁内重新读取合并、临时文件 `fsync + replace`、确定性 observation ID 和有界 observations。explicit 成功证据有效 30 天，heuristic 成功证据有效 7 天，同 scope 使用未过期最小值。
- pending calibration 在重试前脱敏持久化；刷新或重启后必须从重新提供的 Key 列表匹配同一指纹。压缩失败、重试失败、取消或异常会恢复当前 Run 原限制且不写成功记录；模型重试成功后必须先写入校准 store，才接受 assistant 内容或执行工具。
- 当前 Run 成功后单调降低最终限制并更新 Session 快照，后续相同 Key+连接+模型的新 Run 复用有效 cap，其他 scope 完全隔离。用户只看到“该连接实际窗口较小，已自动调整为 X”的双语短提示，同一 Run 刷新不会重复。
- AgentRun 创建时间改为进程内单调微秒精度，避免同秒随机 ID 导致较新的 64K 校准事实被旧 Session 快照拒绝；follow-up 同时冻结点击时的目标 AgentRun ID，关闭保存消息期间活动上下文清理造成的孤立消息竞态，并继续使用既有 409→queue 恢复语义。

## 文件树、用量与复杂 Goal 验证

- 文件树搜索改为流式递归：优先当前目录并逐级扩展，按路径去重增量渲染，提供进度和结果上限；服务端回退、目录缓存、取消与 latest-wins 防止旧请求覆盖新结果。
- 文件树新增 roving tabindex 键盘导航，支持上下移动、Enter 打开、Alt/Ctrl+↑ 或 Backspace 返回上级、Escape 清空搜索；进入目录后焦点稳定，桌面和窄屏继续使用同一树结构。
- 顶部用量与 Session 信息增加缓存命中率，使用 cache/input 口径并兼容不同上游缓存字段；没有上游缓存事实时显示 `—`，不把未知值伪装为 0%。
- 增加复杂 Goal 用户补充后的真实 bundle/direct classic 验收：waiting_user 前后刷新、切换 Session、普通消息唯一 successor、同 Session/Goal/revision/步骤/权限、单轮 usage 和已成功工具不重放均被固定；上游失败后保持可解释门禁并可安全恢复。

## 协作互斥与发布流程

- 新增 Codex/DSH 共用的跨运行时 owner lease CLI。租约存放于当前 worktree Git-dir，绑定 runtime、审批/开发身份、stage、基线 HEAD、relay/lease ID 与 TTL；原子竞争保证同一物理 worktree 只有一个开发写者，Approval Agent 始终只读。
- 过期租约只能显式 reclaim，并先审计 HEAD 与暂存区；cached 非空、状态损坏或身份不确定时 fail-closed。租约只提供工作区写入互斥，不授予 push、tag、release、删除或线上配置权限。
- approval-relay v2 固化 QUICK/STANDARD/STRICT 风险门禁、差量 relay、重复投递防护、自动接管恢复和发布冻结边界；根目录与 Code 两级协作规则统一引用同一 canonical 协议。
- 发布流程新增 canonical `--prepare`、`--publish-prepared` 与 `--resume`：prepare 在本地完成远端预检、正式门禁、EXE 和机器凭证，不创建提交、标签或远端对象；publish-prepared 只有在候选、验证定义、发布说明、EXE 与环境指纹完全一致时复用验证。
- resume 逐项审计发布提交、master、tag、GitHub Release 和资产，一致则跳过、缺失才补做、不同立即停止；禁止 force-push、删除/重建标签或 Release、覆盖不同资产。原有一次性 `python release.py 0.6.4 --yes` 与 `--dry-run` 语义保持不变。

## 验证与兼容边界

- 上下文预算与官方目录分别通过 bundle/direct classic 真实 H4；实际窗口校准最终为 `2 passed`，证明实际失败 Key 的 A-only 单次恢复、其他 Key 零请求、64K AgentRun/Session/reload、提示去重及 follow-up 下一 Run 时序。
- 复杂 Goal 补充续接 H4 为 `3 passed`；文件树、用量、owner lease、发布状态机、Agent protocol、Model Runtime、Session 恢复和前端模块均有定向自动回归。Harness replay 保持 `17 fixtures / 124 events / 25 checkpoints / 25 recoveries / 4 explicit recoveries`。
- 发布门禁已按当前完整测试规模调整共享 pytest 预算，并同步 AgentRun、Goal、手动压缩和前端构建回归夹具事实；测试命令、执行顺序、fail-fast、prepared 凭证绑定与 H4 排除边界不变。
- 旧 Session、AgentRun、模型缓存、Key 设置和 direct classic 继续兼容；新增字段均为可选。Agent protocol 版本保持 v1，不迁移或静默重写历史 JSONL；Goal sidecar、用户凭据和业务数据不会进入上下文目录、校准事实或发布凭证。
