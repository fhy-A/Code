# Code v0.6.3 Release Notes

日期：2026-08-16

<!-- code-release-notes:body:start -->
## 更新重点

- 推出 Goal v2 持久工作流：显式 `/goal` 与普通复杂任务中的模型自主 Goal 共用 Session 隔离的事件事实源、受控 Goal 操作和普通前台 AgentRun，支持计划、逐步证据、用户门禁、跨 AgentRun 续接及确定性终态。
- 工程化系统提示词为固定 11 段纯组装与首次持久化 AgentRun 任务快照；同一任务的续轮、steer 与图片兼容重试复用快照，新任务重新读取动态项目上下文。
- 移除顶部工具日志重复面板，保留对话流内联工具组、Session 工具统计、Branches、Preview 和公共顶部面板；同时完善运行中工具标题提示、折叠层级、工具终态与公开过程投影。

## Goal v2 持久工作流

- Goal v2 使用独立的 `data/goals-v2/<sessionId>.jsonl` 作为当前事实源，采用 append-only 版本化事件、严格 reducer、单调 revision、CAS、稳定幂等键、跨进程锁、损坏 fail-closed 和 clear tombstone。目标创建、计划设置或修订、步骤开始或完成、门禁、暂停、恢复、取消、清除及 Goal 完成都有可审计事件。
- `goal_created` 可以先记录尚无步骤的目标，并由服务端绑定可信的来源消息、顶层 AgentRun、权限档以及 `explicit` / `autonomous` 来源；模型不能伪造身份、覆盖其他 Session 的 Goal 或提升文件、命令、授权和其他副作用权限。
- 显式 `/goal` 先持久化目标，再由普通前台 AgentRun 规划和执行。复杂、多步骤、可能跨 Run 的普通任务也可由模型调用受控内部操作自主创建 Goal；简单任务不会由前端关键词、消息长度或服务端启发式自动升级。
- 计划包含 3～8 个产品级步骤及有界验收条件，公开步骤状态始终只有 `pending`、`in_progress`、`completed`。模型只能通过窄操作设置或修订计划、开始当前步骤、提交与验收条件逐项对应的证据，以及提出 `waiting_user`、`blocked` 或 `failed` 门禁。
- 最后一步满足自身验收条件后，在同一 CAS、幂等和可恢复链中直接写入 `goal_completed`，不再为每个 Goal 强制增加通用的“待验收”终态。需要用户实操判断时，该要求属于仍在进行步骤的门禁；用户要求调整时可继续修订计划而不会伪造完成。
- 顶层 Goal Run 在约 40 轮进行服务端软交接，50 轮保留为单 Run 硬熔断。唯一后继 Run 复用同一 Session、Goal、来源、模型连接和权限，并从有界公开 checkpoint 继续；刷新、多标签、重连或服务重启不会重复创建后继 Run，也不会重放已经成功的工具副作用。连续多个 Run 没有 Goal revision、新公开工具证据或只重复同一终态错误时，流程转为用户门禁。
- Child、detached、parallel、后台恢复及跨 Session Run 不能创建、接管或推进顶层 Goal。Goal 内部操作不进入普通工具组、工具计数、标题或高光，但事件、证据和逐 Run 审计仍由服务端保留。

## Goal 状态与消息体验

- composer 上方新增唯一紧凑 Goal 进度条，显示目标摘要、生命周期或门禁、当前步骤的 1-based 序号和总步数。悬停、聚焦、点击或触摸可以查看仅含步骤序号、三态状态和描述的轻量详情；外部点击、焦点离开或 Escape 会收起详情。
- 只有显式 `/goal` 的可信来源用户消息显示 Goal 标记；只有显式 Goal 真正完成时，完成它的最终助手消息显示从 Goal 创建事件到完成事件计算的“已在 xm xxs 内达成目标”。自主 Goal 不显示这两类历史标记。
- 同一顶层用户消息触发的多个续接 AgentRun 只在最终可见助手消息显示一份去重汇总用量；全局用量和后端逐 Run 审计不变。助手 footer 从左依次排列用量、显式 Goal 完成标记，并在悬停、键盘聚焦或触屏操作时显示复制和消息时刻。
- 模型明确输出的执行进展、证据发现和阶段性小结实时进入本轮“处理中/已处理”折叠组，私有 reasoning 与内部 `goal_*` 工具详情不公开。最后一步完成后的既有无工具终态轮负责输出唯一、完整、面向用户的最终总结，不以“见上方总结”替代，也不增加额外模型轮次。

## 系统提示词与任务快照

- 系统提示词组装迁入独立模块，固定 11 段名称、顺序和条件；安全段仍位于首位，权限说明仍位于末位。纯组装器只接收显式输入，不直接读取前端状态、Skill 加载器或隐式全局数据。
- 每个首次持久化的 AgentRun 建立不可变任务快照；同一 Run 的续轮、steer 与图片兼容重试复用相同 system 内容，queue 真正开始的新前台轮以及新的 detached、parallel 和 Child Run 各自建立新快照。
- 时间标签改为本地 IANA 时区名和 UTC 偏移，并提供安全回退；Child 控制提示词统一为中文，同时要求输出语言跟随委派任务。Child 不继承主 Agent 的自定义 prompt、项目上下文、记忆或 Skill，也不会提升权限或获得递归委派能力。

## 工具组与界面整理

- 删除顶部工具日志入口、面板及专属渲染、详情、开关、样式和中英文文案，避免与对话流内联工具组重复；Session 工具数量统计、Branches、Preview 和共享顶部面板行为保持不变。
- 运行中的外层工具组标题只在当前真实工具标题文字上显示间歇高光；当前工具完成后立即停止，工具间隙保持当前标题，组内仍有后续工具时不会提前显示终态总结。整个工具组结束后，多工具组使用总结标题，单工具组保持该工具标题。
- 工具组首次展开不再自动展开首个工具详情；外层组、单个工具详情、Diff、Selection、键盘焦点和用户折叠选择继续使用稳定 DOM，并在刷新、steer、取消和跨 Run 恢复后保持正确归属。
- 工具调用以 `(agentRunId, toolCallId)` 跨 steer 与取消闭合真实 `succeeded`、`failed` 或 `cancelled` 终态；任一 AgentRun 结束时不再残留“执行中”“等待执行”或运行高光。

## 验证与兼容边界

- Goal v2 最终职责收口定向测试为 `33 passed`，相关 Goal、前端、Session 与 AgentRun 回归为 `400 passed + 66 subtests`，统一 UI 为 `231 passed`；Harness replay 保持 `17 fixtures / 124 events / 25 checkpoints / 25 recoveries / 4 explicit recoveries`。
- bundle/direct classic 核心 Goal H4 `2 passed`，另有显式、自主、跨 Run 和用户门禁等真实路径 `7 passed`；前端 build/freshness、Node/Python 语法和差异门禁通过，并完成 Code Dev 与 direct classic 多轮人工验收。
- 本版本选择 Goal v2 方案 B，不导入或兼容此前实验性的 Goal v1 与短 Planner/workflow 事实源。旧 `data/goals/` 和 `data/goal-workflows/` 文件原地保留但不会被 Goal v2 读取、迁移或改写；旧会话没有 v2 sidecar 时继续按无 Goal 会话工作。
- 现有 Session JSONL 与 AgentRun v4 保持向后兼容；新增消息元数据为可选投影，缺失可信 Goal 绑定时安全地不显示来源或完成标记。默认 bundle 与 direct classic 继续共享相同语义。
