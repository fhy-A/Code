# Code v0.6.9 Release Notes

日期：2026-09-08

<!-- code-release-notes:body:start -->
## 更新重点

- Skills 默认页面改为全部卡片总览，支持搜索和启用开关；进入详情后，左侧目录与右侧内容可独立浏览。全库导入、旧浏览器停用偏好迁移集中在总览，单项详情保留编辑、来源、版本、依赖及高级管理入口。
- 主模型可以根据任务按需加载 Skill，并在执行过程中追加允许组合的能力；显式调用继续可用。真实加载事件显示在工具轨迹中，不再用耗时标题中的 Skill 胶囊代替调用记录。
- 新增不可变 Skill 修订、来源确认、管理事务与受控资源绑定。运行固定到已确认修订，文件篡改、来源冲突、陈旧状态和未完成事务会被明确拒绝或要求处理，避免悄悄改用其它内容。
- 优化目录和详情读取，减少卡片逐项请求；启停操作立即显示“正在处理…”，服务端确认后更新状态。成功写响应可复用已核验的列表，后端减少同一调用中的重复元数据计算。

## Skill 执行与管理

- Skill 注册、激活、运行时归属、生命周期与完成证据形成分阶段合同；执行资源与依赖限定在已加载 Skill 的受控范围，任务结果不能借用加载之前的普通工具结果冒充完成证据。
- 管理操作采用预览、代次校验、固定操作标识与原子事务，支持响应丢失后的同操作重试以及启动恢复。不可变修订保留运行与恢复所需的固定对象，启停、编辑或管理操作不会直接改写已有运行绑定。
- 自有资源与依赖安装接入管理和执行链路；安装后的绑定、失败、取消和恢复继续受原权限与数据目录归属控制，不扩大工具、子任务或工作区权限。

## 默认值、升级与回退

- `CODE_SKILL_IMMUTABLE_ADMISSION_V1` 与 `CODE_SKILL_MODEL_LOADING_V1` 在未配置或空值时默认开启；`0`、`false`、`no`、`off` 可以显式关闭。完成强制门禁 `CODE_SKILL_COMPLETION_ENFORCEMENT_V1` 仍独立且默认关闭，其它实验开关不随之开启。
- 旧 Skill 库不会自动转换为新的管理格式，也不会自动确认冲突来源或重置启用、选中、修订及旧浏览器停用偏好；需要处理的状态由管理页面提示。已有本地内容和删除意图继续保留。
- 新加载协议使用 AgentRun v7；已有 v5/v6 记录不迁移，Session 格式不变。当前版本关闭新加载开关后仍可读取既有 v7 和固定对象；旧二进制不支持 v7，回退前须排空相关运行并保留完整数据，不得通过改写记录版本或删除字段伪装兼容。

## 发布流程

- 发布前将语法、差异、说明和环境检查前置，长验证与构建保留实时输出和完整本地诊断。默认完整发布、准备、发布已准备候选及断点续发共用原有凭证约束；只复用与当前候选、环境、验证定义和产物完全匹配的结果，失败或漂移不会跳过验证。

## 本次验收说明

- 本版本经用户明确授权采用一次性差量验收：原完整 pytest 为 2751 通过、1 跳过、1 失败及 1453 个子测试通过，耗时 1067.26 秒；失败记录保留。仅修正取消/超时测试的一行内容就绪等待，两个原参数分支连续各10次、共20次补验通过，全部原断言、参数、超时及生产代码保持不变。
- 修复后没有重跑完整测试，不能将该补验解读为全量通过。本地产物使用独立例外审计，不生成标准 prepared 凭证；常规发布门禁没有修改。

## 已知限制

- Skill 目录和启停仍可能有秒级等待。合成同基线测试中的后端启停链耗时约减少13%，不代表真实用户环境的低延迟承诺；即时反馈已改善，进一步性能优化延期。
- 真实模型短样本中，显式调用已观察到有效加载收据，但两项自然任务未观察到自主加载。当前不宣称自然选择稳定，也不将界面调整视为用户体验验收全部通过。
- 既有 PPTX / LibreOffice 渲染超时及部分进程退出证据不足仍未解决，本版本不宣称 Office 渲染问题已修复或所有真实任务均已验证。
