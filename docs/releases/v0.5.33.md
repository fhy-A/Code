# Code v0.5.33 Release Notes

日期：2026-08-04

<!-- code-release-notes:body:start -->
## 更新重点

- 建立事件驱动 Agent Harness 的分阶段基础：加入版本化 Agent 事件契约、纯 Run reducer、规范投影视图、前后端只读影子比较和确定性离线 replay，继续兼容旧 AgentRun、旧会话 JSONL 与经典前端回退。
- 新增同轮引导与显式排队能力。任务运行中发送的后续要求可以由当前 Agent 继续处理并判断优先级；需要独立执行的消息仍可排队，前台与后台任务的运行状态和投影相互隔离。
- 完善多模态图片管线：统一模型可接受的图片格式，修复声明 MIME 与实际编码不一致、旧会话无效图片持续污染后续请求等问题；发送图片按批次横向排列并采用统一预览高度。

## 运行稳定性

- 恢复真实流式增量展示，修复输出中途暂停后正文被替换的问题；暂停时保留已输出内容并追加暂停说明。
- 完善模型、命令和同轮多工具的取消生命周期：正在执行的命令能够终止，未开始工具写入耐久取消终态，不再残留“执行中”或“等待执行”，重复取消保持幂等。
- 补齐命令失败结果的退出码、stderr 和单次执行验证；授权接受/拒绝、问卷、排队、后台任务与工具刷新恢复均加入投影和回归保护。
- 修复运行中刷新后的累计计时回退、状态短暂消失、前后台影子混用及重复 Runtime 消费等问题，并增加首次模型增量的 metadata-only 状态检查点。

## 交互与维护

- 优化工具组的阶段标题、展开状态与完成统述，避免执行中在具体工具名和笼统描述之间跳动。
- 改进模型目录刷新、斜杠命令本地化、手动上下文压缩历史保留、会话导入反馈和 workbar Key 状态文案。
- 继续完成前端模块职责拆分与 bundle/经典页面兼容收口，为后续 Harness 场景覆盖和浏览器 E2E 门禁保留可回退基础。

## 已知限制

- 若在首个模型增量到达前立即刷新页面，界面可能持续显示“已提交模型，正在等待响应”，并在任务结束后一次性恢复正文。该场景已经记录为后续刷新恢复专项，不影响普通对话、工具执行和任务取消，但本版本不宣称模型运行中刷新已经完全解决。
- Harness H2 仍处于真实样本复验阶段；当前发布的是已经自动验证和人工验收的路径，不代表后续 Harness 工程全部完成。

## 兼容与验证

- AgentRun v1～v3、旧会话 JSONL、现有工具协议、经典前端回退和正式/开发端口隔离保持兼容，不需要改写历史会话。
- 发布前基线验证为 1006 项测试及 468 个子测试通过；前端构建与语法校验通过，15 条 Harness replay 夹具覆盖 106 个事件、17 个检查点恢复和 4 个显式恢复点。
