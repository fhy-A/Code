# Harness H1-2 服务端事件协议影子验证

完成时间：2026-08-02 20:23（Asia/Shanghai）

基线提交：`59d6845`

阶段性质：服务端内存影子观察，不改变事件、持久化或前端行为

> 后续状态：H1-3 已在开发实例灰度启用显式事件 `protocolVersion: 1`，并增加前端旧事件、v1、未来版本与畸形事件兼容；正式实例仍默认写入旧格式。当前边界见 [`h1-3-versioned-event-grey-rollout.md`](h1-3-versioned-event-grey-rollout.md)。以下内容保留 H1-2 完成时的阶段事实。

## 1. 阶段目标

H1-2 将 H1-1 的纯事件契约接入当前 AgentRun 产生事件的边界，但只作为兼容模式观察器：

1. 检查新产生事件的 v1 兼容归一、序号和 Run 状态迁移；
2. 观察器失败时继续执行原事件写入、持久化和任务终态；
3. 诊断只保留有上限的脱敏结构字段；
4. 开关关闭后完全回到原事件路径；
5. 不给当前事件增加字段，不迁移旧 AgentRun 或会话 JSONL。

本阶段仍未替换前端投影，也未把规范化事件写回磁盘。

## 2. 开关与实例默认值

环境变量：`CODE_AGENT_PROTOCOL_SHADOW`

| 场景 | 默认行为 |
| --- | --- |
| 开发实例 `INSTANCE_MODE=dev`（通常为 3011） | 开启影子观察 |
| 正式实例 `INSTANCE_MODE=release`（通常为 3010） | 关闭影子观察 |
| 显式 `1/true/yes/on` | 开启 |
| 显式 `0/false/no/off` | 关闭 |
| 空值或其他无法识别的值 | 回到对应实例默认值 |

因此正式实例不会因为环境变量拼写错误而意外开启。需要立即回退时，设置 `CODE_AGENT_PROTOCOL_SHADOW=0` 并重启对应实例即可；不需要修改数据。

## 3. 接入边界

影子观察只接入三个现有边界：

- `_append_agent_event()`：观察普通耐久事件；
- `_finish_agent_run()`：观察绕过普通追加函数的终态事件；
- `_agent_run_from_record()`：从旧记录恢复时，以已有最大序号为游标创建新的内存观察器。

新 Run 从游标 0 和 `model` 状态开始；恢复 Run 从 `nextSeq - 1` 和恢复后的实际状态开始。这样服务重启后只观察后续事件，不重新解释或改写旧文件，也不会把恢复后的第一条事件误报为序号间隙。

观察调用位于 AgentRun 的既有可重入锁内，以保持并发追加时的观察顺序。所有契约调用均由 fail-open 边界包裹；任何规范化、序号或迁移校验异常只增加脱敏计数，不向正式事件路径抛出。

## 4. 内存状态与脱敏边界

每个启用观察的 Run 只在内存中持有：

- 已观察、已接受事件数；
- 已观察的 Run 状态迁移数和最后状态；
- 脱敏诊断代码计数；
- 最多 64 条去重诊断样本；
- 最多 256 个最近事件内容指纹；
- 观察器自身异常计数。

诊断样本只允许以下字段：

```json
{
  "code": "missing_payload_fields",
  "severity": "warning",
  "source": "append",
  "eventType": "tool_started",
  "seq": 4
}
```

不会保存契约错误文本、路径、事件载荷、命令、文件内容、模型内容、Key 或其他值。未知来源统一记为 `other`，未知事件类型统一记为 `unknown`；诊断代码达到上限后聚合为 `other_diagnostics`。重复样本只累加计数，不继续占用样本空间。

当前生产事件仍没有 `protocolVersion`，因此 `legacy_unversioned_event` 是预期的信息级诊断。它会按事件累计，但每种事件只保留一条结构样本。

## 5. 数据与协议兼容性

以下边界由实现和测试共同锁定：

- 原事件信封仍为 `{seq, type, data, createdAt}`；
- `_agent_run_record()` 不包含影子状态或诊断；
- AgentRun 磁盘 JSON 不包含影子状态或诊断；
- `_agent_snapshot()` 和 HTTP 响应不包含影子状态或诊断；
- 会话 JSONL、工具协议、模型请求、前端状态和经典回退页面均未修改；
- 旧 AgentRun 不做原地迁移，恢复后从已有游标继续；
- 关闭开关后，新 Run 不创建影子状态，事件序号和内容保持原行为。

内部 `_agent_protocol_shadow_snapshot()` 仅供自动测试和本地诊断使用，不是 HTTP API。

## 6. 自动验证

定向验证覆盖：

- 开发/正式默认值、显式开关和异常值回退；
- 普通事件、终态事件和 Run 状态迁移；
- 15 条 H0 脱敏轨迹的 106 个事件；
- 服务重启后的持久游标续接；
- 观察器异常不阻断事件写入；
- 诊断脱敏、64 条上限与 256 个指纹窗口；
- 公开快照、持久记录和原事件信封零新增字段。

H1-1/H1-2 与 Agent 运行时定向结果为 `92 passed, 171 subtests passed`；完整回归为 `949 passed, 419 subtests passed in 67.55s`。`npm run check:frontend` 通过 bundle、构建新鲜度、JavaScript 语法和经典回退门禁；Python 语法与 `git diff --check` 通过。

真实假上游完整终态链没有出现序号间隙、乱序、缺少必需载荷、未知事件或非法 Run 迁移。15 条 H0 轨迹也全部被服务端影子入口接受。

## 7. 回退与下一步

最快回退方式是设置 `CODE_AGENT_PROTOCOL_SHADOW=0`；由于没有新增持久字段或数据迁移，已有和新建会话均无需处理。代码级回退可单独撤销本阶段提交，不依赖回退 H1-1 的纯契约模块。

下一阶段保持独立确认：

1. 先基于影子结果判断是否需要修订事件最低字段或迁移表；
2. 再决定新写入事件是否显式增加 `protocolVersion: 1`；
3. 前端对版本字段、旧无版本事件和未知事件的适配另行实施与回退；
4. H1 收口后再进入 H2 reducer 与影子投影，不在 H1-2 混入 UI 状态重写。
