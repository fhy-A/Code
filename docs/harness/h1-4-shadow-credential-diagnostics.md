# Harness H1-4 影子凭据诊断分层与 H1 收口

完成时间：2026-08-02 22:18（Asia/Shanghai）

阶段性质：修正开发实例真实事件观察中发现的诊断级联，不改变正式事件、工具结果、持久化数据或界面行为

## 1. 发现与影响

H1-3 完成后，对最近 5 个真实 v1 AgentRun 做只读结构审计：共 221 个事件、73 个 `tool_started`，5 个 Run 均为完成态，事件原始序号连续且全部使用 `protocolVersion: 1`。

首次按 H1-1 契约离线重放时，其中 2 个 `tool_completed` 的结果包含源代码或文档里的密钥样式示例。原凭据扫描对默认兼容模式和严格模式都直接抛错，导致这两个事件没有推进影子校验游标；后续合法事件因此被连带记录为 `event_sequence_gap`。实际事件没有缺失，任务、前端投影和持久化也没有失败，异常只污染了影子诊断。

## 2. 分层规则

凭据规则现在分为两个明确入口：

- 默认和 `strict=True`：继续递归拒绝敏感字段名及凭据样式文本，保持 H1-1 契约、安全测试和未来正式写入口的严格边界；
- 服务端生产影子观察：使用显式 `credential_mode="diagnose"`，只生成不含原值的结构诊断，然后继续执行信封与序号校验；
- 敏感字段名记录为 `credential_bearing_field` / `error`，普通文本命中凭据样式记录为 `credential_like_text` / `warning`；
- 每类命中在一次事件规范化中最多保留一条诊断，不把匹配值写入消息、异常、影子样本或持久状态。

严格模式即使显式传入诊断模式仍会拒绝，避免调用者绕过契约测试。影子观察仍是 fail-open：真正的规范化异常继续增加 `contractErrors`，但“疑似凭据文本”不再伪造成观察器自身错误或后续序号缺口。

## 3. 数据兼容与回退

本阶段没有修改：

- AgentRun `version: 3`、事件信封或事件载荷；
- `tool_completed.result`、会话 JSONL、模型消息或前端投影；
- 开发实例 v1 写入和正式实例旧格式写入的默认值；
- H1-2 的内存上限、脱敏样本字段及功能开关。

最近真实 Run 的原始工具结果保持不变，本阶段不重写任何 `data/agent-runs/*.json`。最快回退仍是设置 `CODE_AGENT_PROTOCOL_SHADOW=0` 并重启实例；代码级回退可单独撤销本阶段，不要求迁移或恢复数据。

## 4. 验证结果

新增回归覆盖：

- 默认与严格模式继续拒绝嵌套敏感字段、`Bearer` 和 `sk-` 样式文本；
- 影子模式对字段名和文本命中生成分级、脱敏诊断；
- 疑似凭据文本事件被序号校验接受，下一事件不产生级联缺口；
- 影子快照不包含匹配原文、路径或工具结果，正式事件和耐久记录保持原样；
- 影子关闭后仍完全回到旧行为。

协议与 Agent 运行时定向结果为 `98 passed, 179 subtests passed`；Harness、前端与稳定性定向结果为 `197 passed, 18 subtests passed`；完整回归为 `957 passed, 427 subtests passed in 90.70s`。`npm run check:frontend`、Python 语法与 `git diff --check` 均通过。

使用相同规范化器和序号校验器重新只读重放最近 5 个真实 v1 Run 后，221/221 个事件全部接受，只保留 2 条 `credential_like_text` 脱敏诊断，规范化异常、序号缺口和其他失败均为 0。

## 5. H1 收口决定

H1 的版本化事件契约、旧事件适配、状态不变量、凭据严格拒绝、开发实例 v1 灰度、前端兼容读取和真实多工具观察已经形成可回退闭环，允许进入 H2。

正式实例继续默认写入无版本旧信封；是否提升正式实例的 v1 默认值保留为独立发布决策，不作为 H2 纯 reducer 与影子投影的前置条件。H2-1 先冻结新旧投影的比较字段、初始状态和纯函数输入输出，不直接接管现有 UI。
