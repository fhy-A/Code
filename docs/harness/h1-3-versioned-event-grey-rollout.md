> 后续修正（2026-08-02 21:55）：开发实例连续刷新测试进一步发现，仅从低频持久化检查点恢复会令计时停住或回退。现已在会话首帧恢复显示态的基础上，增加仅限当前浏览器标签页、同一 `agentRunId` 且 30 秒内有效的短期计时检查点；刷新时取耐久值与短期续算值的较大者，恢复接管时再与当前显示值合并，终态和取消时清理。该修正不启动模型、不生成事件、不修改 AgentRun 或会话 JSONL；过期、跨 Run 和不可用存储均安全回退到耐久值。

## 1. 阶段目标

H1-3 在 H1-2 影子观察通过后，完成事件版本从“仅有契约”到“可灰度写入和兼容消费”的最小闭环：

1. 新事件可显式写入 `protocolVersion: 1`；
2. 开发实例先默认开启，正式实例继续默认关闭；
3. 前端在同一 AgentRun 中兼容无版本旧事件、v1 事件和未来版本事件；
4. 旧 AgentRun、会话 JSONL 与 H0 夹具不做原地迁移或静默改写；
5. 关闭开关后，服务端立即恢复原四字段事件信封；
6. 不改变现有 UI 投影、工具协议、模型请求或 AgentRun 记录版本。

## 2. 写入开关与灰度范围

环境变量：`CODE_AGENT_EVENT_PROTOCOL_V1`

| 场景 | 默认行为 |
| --- | --- |
| 开发实例 `INSTANCE_MODE=dev`（通常为 3011） | 新写入事件包含 `protocolVersion: 1` |
| 正式实例 `INSTANCE_MODE=release`（通常为 3010） | 继续写入无版本四字段旧信封 |
| 显式 `1/true/yes/on` | 开启 v1 写入 |
| 显式 `0/false/no/off` | 关闭 v1 写入 |
| 空值或无法识别的值 | 回到对应实例默认值 |

H1-2 的 `CODE_AGENT_PROTOCOL_SHADOW` 与本开关相互独立：前者控制内存观察，后者只控制新事件信封。需要回退 H1-3 写入时设置 `CODE_AGENT_EVENT_PROTOCOL_V1=0` 并重启对应实例即可；前端兼容读取器可以继续保留。

正式实例本阶段没有改变默认写入格式。后续只有在开发实例真实任务、刷新恢复和混合历史续接均确认正常后，才单独决定是否提升正式实例默认值。

## 3. 服务端事件边界

普通事件和终态事件统一通过 `_build_agent_event()` 构建，避免两条写入路径产生不同信封。开启 v1 后，新事件格式为：

```json
{
  "protocolVersion": 1,
  "seq": 7,
  "type": "tool_started",
  "data": {},
  "createdAt": "2026-08-02T12:51:00Z"
}
```

v1 `createdAt` 使用真实时区换算为 UTC，再输出严格的 `Z` 时间；不会把本地时间直接拼接 `Z`。已有时区输入按其偏移换算，无时区的内部时间按系统本地时区解释。旧模式仍保留原时间文本，全局 `now_iso()` 和 AgentRun 的 `createdAt/updatedAt` 表达没有改变，避免事件版本灰度间接扩大为 AgentRun 元数据迁移。

AgentRun 恢复时不重写历史事件。一个从旧记录恢复并继续执行的 Run 可以自然包含无版本旧事件和带版本的新事件，事件序号继续递增。

## 4. 前端兼容适配

`agent-runtime.js` 在耐久事件进入现有投影前统一执行 `normalizeAgentEvent()`：

- 无 `protocolVersion`：按兼容 v0 读取并归一到当前 v1 形状；
- `protocolVersion: 1`：按当前信封读取；
- 更高的未来版本：保留已知信封字段和原事件类型，附加诊断后交给现有投影；
- 未知事件类型：不崩溃，现有投影无对应分支时自然跳过；
- 合法序号但空类型等畸形事件：不投影，但推进耐久游标，避免轮询永久卡在同一坏事件；
- 非法或缺失序号：不推进游标，避免跳过无法确定顺序的数据。

归一后的事件只包含当前规范信封；未来信封的未知顶层字段不渗入 UI 状态。兼容诊断只随本次回调提供，不写回 AgentRun、会话 JSONL 或浏览器持久状态。

## 5. 数据兼容与回退

本阶段锁定以下边界：

- AgentRun 记录仍为 `version: 3`；
- 旧 AgentRun 与现有 `data/` 文件不迁移、不重写；
- 会话 JSONL、消息格式、工具端点和模型请求不变；
- H0 的无版本脱敏轨迹继续作为旧协议回归基线；
- 默认构建与经典回退页面继续使用同一前端兼容入口；
- 关闭服务端开关后，新事件恢复为 `{seq, type, data, createdAt}`；
- 即使回退服务端写入，前端仍可读取此前已经产生的 v1 事件和旧事件混合历史。

因此最快回退只需关闭 `CODE_AGENT_EVENT_PROTOCOL_V1`，无需处理历史文件。代码级回退可单独撤销 H1-3 提交，不要求回退 H1-1 契约或 H1-2 影子观察。
