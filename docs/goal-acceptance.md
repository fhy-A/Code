# Goal 验收来源与异常工具文本

## 验收语义与来源

用户要求执行并对照预期的客观检查使用 `machine` 条件；不能额外创建“用户再确认结果一致”的条件。真正缺少的用户输入、明确要求的主观验收或授权条件保留 `user` 类型与现有 gate。来源校验不判断自然语言含义，也不把模型填写的 `purpose` 当作授权票据。

新建前台 Run 的可选 `goalAcceptancePolicy: 1` 启用来源校验。新增或改变的用户条件需提供 `sourceReference` 的 `messageId`、原文子串 `quote`（最多 1000 字符）及 `purpose: input|judgment|authorization`；服务器核对实际来源并生成 `version: 1`、整段来源文本的 SHA-256 `contentHash`。也接受与真实来源一致的完整五字段引用。不能用工具输出、模型总结或不存在的消息 ID 代替真实来源。

可引用来源包括当前 Goal 起点至当前 Run 起点之间的已验证前台用户消息，以及当前/相关前台 Run 控制器已消费的 steer 和实际提交的 `request_user_input` 回执。追加消息用已消费回执的内容哈希绑定；问答只暴露实际回答或用户选中的选项文字，不暴露问题标题作为用户回答。待消费、取消、未回答的输入不能充当已收到的验收证据。Run 恢复及上下文压缩后仍从既有回执和持久会话查找，不创建新的审批工具或持久来源库。

来源校验只证明“这段文字来自这里”。模型仍须依据用户真实要求区分输入、判断和授权。`input` 可引用已经给出的同一条原始输入；`judgment`/`authorization` 的完成证据不能直接复用当初要求等待确认的那条来源。执行权限、既有 Skill 验收与 Goal reducer 门禁保持原合同。

## 读取、兼容与恢复

`goal_read` 保留现有步骤、条件及文本分页；条件的 `sourceReference` 返回完整五字段，包括原始引文。普通汇总可能按原预算裁剪条件，但 `stepId`、`offset`、`textOffset` 可以取回原条件及完整引用，合法修订其他待开始步骤时无需猜测引文。来源列表另用 `userSourceOffset` 分页；长来源以 `userSourceMessageId`、`userSourceTextOffset` 每页读取 100 字符。列表序列化不超过 1000 字符；Goal 聚合投影继续受 24000 字符预算约束。

查找会话最多读取末尾 64 MiB / 50000 行，保留最多 256 段 / 2 Mi 字符；历史回执最多读取 32 个相关前台 Run，单文件 8 MiB、合计 32 MiB，每个 Run 最多返回 128 条回执来源。边界缺失或达到限制通过分页信息明确报告。无法确认历史起点时，只接受独立确认的当前输入及已有控制器回执，不猜测历史归属；来源不可用时失败，不伪造引用。纯图片等没有可引用文本的输入不生成文字引用。

旧 Run 缺失 `goalAcceptancePolicy` 时保留原合同，包括已经启用 bounded closeout 的旧 Run：继续使用持久化的旧工具定义与原有有界收尾，不收到无法调用的来源参数要求。`tests/fixtures/goal-legacy-tools.json` 固定基线的 11 个 Goal 定义用于恢复验证。旧条件没有引用，不被自动降级、移除或补造来源；未改变的条件可在修订其他待开始步骤时原样保留。已开始步骤仍由原 reducer 禁止改写条件。后续真实用户输入/验收到达时，新 Run 可用原有 `user` 证据路径完成旧条件，无需取消或重建 Goal。指定真实旧 Goal 与事件不迁移、不重写。

协议版本仍为 Goal v2；新 reader 接受上述可选字段，旧事件缺省字段不变。旧二进制的严格 reader 不认识新 `sourceReference`，因此一旦产生新引用事件，不能直接换回旧二进制读取这些事件。需要回退业务行为时应保留可选字段的读取/校验兼容层，再撤回来源策略与界面行为；不通过删字段或重写事件回退。上线/回退均不在本候选授权内。

## 工具投影与 DSML

工具开始、等待和终态按 Run ID + call ID 合并后再分组；编辑卡仍保留，同 ID 的不同 Run 不合并。旧消息缺少 Run ID 时以用户轮次隔离。实际开始前保持等待，实际开始后显示运行，收到成功/失败/取消终态后使用该终态；不会因整个 Run 结束而强制成功。重复消息只影响投影，不改写历史。

内部 `goal_read` 与其他 Goal 控制工具一致隐藏，空白回答不出气泡；有意义的说明与明确等待用户的正文保留。

针对已观察到的完整裸 DSML `calls`/`invoke` 外壳做词法识别：允许普通进度正文之后从独立行开始的协议块；代码围栏、缩进代码、引用和行内示例仍按文本处理。不解析参数、不执行伪工具、不把这轮存成有效 native replay。模型流必须先通过原协议完整性校验，取消与输出截断保持原优先级；异常普通回答与压缩摘要以 `tool_protocol_error` 停止，不重试业务操作。诊断保留块外进度正文，说明该轮没有执行工具。

识别范围是该完整外壳，不宣称覆盖所有供应商标记或损坏变体。已有历史仅做展示和下次请求过滤，原始事件不改；若严格 native 历史链已依赖被排除的异常文本，原严格校验仍可能拒绝恢复，不能补造合法回放记录。
