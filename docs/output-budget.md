# 编码 Agent 单次输出预算与截断停止（CODE-102 第一阶段候选）

本阶段只解析预算、准确停止截断并显示诊断，不实现截断后的自动恢复，也不改 Goal/Skill 事件或既有权限。候选数字只验证了请求构造与边界，尚无自然任务成本/效果对比，不代表最优值。

## 偏好与预算入场

日常设置显示“单次输出：自动”；已有手动值显示“自定义”，具体正整数和快捷值位于默认折叠的高级设置。真实设置页和隐藏原始表单共用 change/保存路径，旧 `code-max-tokens` 数字保持手动意图，旧 `auto` 在新请求采用新策略。回答详细度、语气及推理强度仍独立。

模型参数区局部采用桌面两列：第一行表达详略/交流语气，第二行单次输出/最大上下文窗口；700px 及以下单列。单次输出的原生 summary 控件与其他输入同为 40px，点击或键盘 Enter/空格就在该字段下展开自定义输入；展开不拉伸其他字段。高级采样保留在参数组下方，默认摘要不显示动态预算数字。

前端自动值 0 仅是本机请求构造占位，创建接口同时收到 `{version:1, mode:"auto"}`；手动意图为 `{version:1, mode:"manual", tokens:N}`。服务端入场编译为具体 `max_tokens`，再由既有推理适配器完成参数命名和固定推理余量检查；OpenAI 适用模型使用 `max_completion_tokens`。冲突、非法正整数或超过已知上限明确拒绝，不暗改手动值。实际编码请求不会把自动占位 0 发给模型。

| 可核验情况 | 自动候选 |
|---|---:|
| 确认支持推理，含 default/low/medium/high；未明确关闭 | 65536 |
| 明确不支持推理，或已确认能力下明确关闭推理 | 32768 |
| 能力未知或未识别别名 | 16384 |

当前复用的本地目录没有单独验证过的编码任务专用默认预算，因此不捏造“已验证模型专用值”，采用上述候选。模型最大输出仅是上限，不直接作为每次默认。自动采用值受可信已知模型/连接上限约束；没有独立推理 token 控制的模型，不承诺硬保留正文。

## 来源与上下文边界

- 推理能力复用精确模型的既有适配器与路由准入证据；default 不等于关闭推理。服务端模型目录中显式布尔 `supports_reasoning` 可声明支持/不支持，未知值不提升能力；明确不支持时拒绝不兼容的显式推理设置，不自动降级。
- 模型输出上限使用当前官方能力目录对精确模型/有效别名给出的 `maxOutputTokens`，独立保留 `modelLimitSource`。没有该字段或来源已失效时保持 unknown，不从上下文窗口推导输出能力。
- 连接限制只来自服务端实际获取的模型目录中有效整数 `max_output_tokens` / `maxOutputTokens`；复用路由刷新采集路径，按标准化 base URL、已准入 connectionId 和精确模型 ID 隔离。相同 URL 下不同连接不混用限制。相同目录重复声明取保守最小值；下次成功刷新重建该连接的声明，缺失字段退回 unknown。未绑定路由的旧目录读取只填自己的空 scope，不能替任意新路由证明限制。
- 这些是目录声明/静态适配证据，不是额外付费探测，也不证明供应商永远遵守声明。`contextWindowHard` 只管理上下文，绝不作为输出可信标志。
- 解析后的实际输出值交给既有上下文/校准/安全余量计算。若无法至少留下原合同要求的输入空间，则拒绝并给出调整入口；不会为塞进上下文而静默缩小输出。正常输入压缩继续使用原有有界机制。
- 新预算合同下，压缩内部请求有自己的实际预算：不超过所选手动/自动上限，固定 thinking 模型仍满足既有 1024 正文余量。压缩本身遇到可靠截断即停止 Run，不再请求业务模型；诊断注明 `kind=compaction` 和该次实际额度。旧在途 Run 的原压缩合同保持。

## 截断、失败与优先序

只接受有完整流终止边界的 `length` / `max_tokens` 事实。三个独立错误码分别为 `output_truncated_reasoning`（有推理内容/有效推理用量且无正文）、`output_truncated_text`、`output_truncated_tools`。诊断仅含实际额度、finish reason 与可用 usage 计数，不复制隐藏推理、工具正文、签名或凭据。缺少细分 usage 时显示未知，不推算正文 token 余额。

用户取消优先。原生协议结构、DONE/finish、thinking 签名等校验仍优先于把损坏流归为可识别截断。Claude 的工具 JSON 解析失败只延迟到终止事实确定：非 length 仍严格拒绝，length 也不修 JSON、不产生可回放 native 条目。即便截断批次内某些参数碰巧是合法 JSON，整批均不执行。正常完整 tool_calls 与原非 length 参数错误的验证边界保持。

截断不进入 reasoning-only 空回复重试、换 key 重试、Skill 修复或 Goal 收尾补查，不自动切换模型或降低推理。之前成功的工具结果和 Goal 步骤保留。失败轮不写入原生回放条目；已显示的截断内容标记 `skipApi`，下一条新请求只使用最后有效历史边界。网络断流等非 length 故障仍按原恢复合同处理，不能把它们冒充输出截断。

## 恢复与回退

- Run 的 `request` 保存实际数值；可选 `outputBudget` v1 保存意图、候选、采用值、模型/连接上限及来源，恢复只核验冻结字段和实际 request，不查询当前目录重解释。
- 可选 `outputDiagnostic` v1 保存 `kind=model|compaction`、错误码、终止原因及计数；未知版本、非法字段/类型或不匹配预算拒绝恢复。旧记录缺失新字段时按旧请求和旧预算读取，不迁移历史 Goal/Session。
- 新自动请求须先由本机 heartbeat 确认 `outputBudgetProtocol=coding-output-v1`，旧服务或未就绪状态阻止自动占位发出；挂接现有 AgentRun 不因此重建请求。配套服务和前端须一同部署。旧客户端只能发送其原来具体数值，服务端不凭数值猜它原本是否为自动。
- 回退在无在途写入的安全停止点进行，配套撤回前后端及构建输出，不重写历史记录。旧二进制不会解释新预算/截断诊断字段；不承诺已停止的截断 Run 在旧版继续执行，使用新用户消息重新开始。未重启真实服务、未刷新用户页面。
