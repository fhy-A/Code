| tabs/active/开关/滚动 | 同项目会话共用，跨会话接续阅读方便 | 各稳定Session分别保存，返回原会话恢复自己的阅读位置 |
| 同项目并行任务 | 在同一份可见工作集中切换时可能互相影响活动标签/阅读位置，需要额外避免抢占 | 切同项目另会话也先隔离，后台完成只更新所属会话 |
| 与改动审查的关系 | 容器虽共享，review仍必须绑定来源Run/版本，不能按project复用事实 | UI选中范围随会话保存，事实仍属于Run/来源版本，较贴合任务归属 |
| 使用代价 | 跨会话少重新打开文件，但不同任务易混在同一阅读集合 | 跨会话需重新打开文件；仍可复用现有项目文件树，无需复制项目 |
| 实施门槛 | 延续原确认的项目标签约束 | 先批准同项目不再共享标签这一变化，并冻结Session/草稿/导入生命周期 |

**推荐B的理由**：任务与改动审查更接近会话上下文，同项目并行任务不应互相改活动文件或滚动位置。项目负责文件组织与工作区上下文；实际访问仍由现有服务端路径/权限规则决定，会话独立不构成新的授权限制或扩大。Codex官方资料中的thread side panel/chat sidebar可作为上下文组织参考，不能证明其持久化或切会话行为与B一致。

第一版只实现用户选定的一种隔离归属，不同时提供A/B切换开关。跨会话分享或复制标签以后可考虑明确动作，不默认互相同步。用户尚未裁决时，A仍是原已确认方案，B仍是推荐候选；本稿其他新建议不构成实施授权。

### 3.2 推荐B的分层与生命周期

- **会话层**：稳定Session身份保存tabs、active、paneOpen、scroll、mode及review选中范围；同项目换会话也先隐藏旧正文并使旧请求失效，返回原会话恢复自己的工作集。文件查重与浏览复用槽仅在该会话内生效，其他会话已打开的同path不能被跨会话激活。Session身份须置于数据源/host命名空间内，来源导入还要核实本地身份及代次，不能只用外部源ID或可重用字符串。
- **项目层**：显式projectId和root集合提供文件组织与工作区上下文，不是访问凭据或硬沙箱；实际访问沿现有服务端路径/权限规则。目录浏览不是归属迁移，项目不负责同步各会话的UI状态。
- **全局层**：宽度、主题等既有UI偏好可继续全局使用，不把文件内容或活动标签也全局共享。
- **Run层**：冻结实际改动事实与来源revision。会话只持有合法review引用，不能因同项目或切会话就把别的Run结果当当前轮。
- **新会话/欢迎态**：默认空工作集。没有Session的临时预览不写回上一会话；如希望保留草稿预览，须使用独立draft身份，只在对应新Session实际落定且scope验证后迁移一次，不广播给后续所有会话。draft的启用和失效方式须在阶段0明确。
- **改归属/导入/生命周期**：Session迁移项目后先核验全部文件scope，不能携带旧项目正文冒充新项目。归档时暂停并隔离其活动侧栏，恢复后再验证；删除后记录按已确认保留策略失效，不能自动继承给重建的同ID；来源导入不自动带入未受信任的路径或外部侧栏状态。具体保留/清理与身份代次仍待确认，阶段1不擅自删除用户原状态。

### 3.3 一个侧栏，两种阅读对象

文件预览用于持续查看项目中的当前文件；改动审查用于回答“这一轮实际改了什么”。共享右侧容器、加载状态、焦点返回、错误呈现和资源释放，分开身份、保留期和生命周期。下表按推荐B描述；若选A，只把文件UI工作集归属改回project，Run事实归属不变。

| 对象 | 归属与身份建议 | 内容性质 | 打开方式 |
| --- | --- | --- | --- |
| 项目文件标签的UI实例 | 数据源/host scope + Session身份/代次 + 经现有API核验的真实文件身份；项目另供组织上下文 | live，沿既有接口读取当前文件 | 文件树、搜索结果、最终回答本地链接；沿用第2节规则 |
| 本轮改动视图 | 数据源scope + 真实请求/AgentRun归属集合 + 结果revision + 文件身份 | 已有执行证据支持的冻结历史结果 | 聊天终态轻量摘要进入，一份review中换文件 |
| 待批准编辑建议 | 原authorization/proposal/tool-call实例身份 | 尚未应用的建议，继续原授权流程 | 原提案卡片和授权定位；不冒充已发生改动 |
| Git工作区变更（扩展） | 明确仓库 + Git范围 + 当前读取revision | 可能含用户及其他写者的现有变更 | 单独标“工作区变更”，不当作本轮Agent归因 |

建议的文字线框（仅供评审，不是新页面原型）：

```text
聊天中的本轮终态
  改动 3 个文件 · 查看改动

现有右侧工作区
  [项目文件] [本轮改动]
  项目文件：README.md  main.py  …  （既有同等标签）
  本轮改动：本次请求 / 时间 / 覆盖说明
             搜索文件…
             新增 a.txt   修改 main.py   删除 old.txt
             选中 main.py 的差异；[查看当前文件]
```

“本轮改动”内部用紧凑可搜索/滚动的文件列表选择一个详情，不为每个文件自动开新标签，不新增可拖拽分栏；当前文件可以显式进入文件标签或既有渲染预览。两种视图在同一侧栏切换时只激活一个详情renderer。

主聊天在完成、失败或取消终态已有实际改动时显示轻量摘要，不把一堆diff展开进聊天、不自动抢焦点。后台任务完成只更新其所属记录/摘要，不切当前项目、会话、标签或页面。仅当覆盖已知完整且确认无改动时不显示；若命令等覆盖未知，即使已记录数为0，也必须提示“改动记录不完整”而非宣称零修改。数值来自执行事实去重后的文件数，不解析模型回答来决定。

## 4. 项目与文件身份：修正共享root和浏览目录假设

以下是UI工作集与文件身份校验的共同约束，A/B都适用，不把UI隔离声称为文件权限隔离；UI工作集按第3节选定归属。具体字段、来源与兼容策略尚待阶段0确认。

1. **先绑定数据源和host。** 同一浏览器来源、同名项目或同一相对路径不足以说明是同一工作区；切换服务数据源/host不得加载旧scope记录。现有产品尚未被本文证明具有可直接复用的稳定scope标识，缺失时标为待解决，不自造不受验证的身份。
2. **显式projectId优先。** 文件树浏览目录与Session归属分开，不因导航、共享root命中或预览文件而迁移Session。无项目的独立文件夹仅在当前scope和受控根验证成功后使用明确fallback，不能借用其他会话或已归属项目的标签。推荐B的无Session预览还必须使用独立draft身份。
3. **文件键不能只是相对path。** 同项目两个root下各有`README.md`时，必须基于API确认的受控真实路径/根身份区分；显示名可用短root提示解歧义。目标必须按现有服务端路径/权限规则解析并核验；projectId和root名单不保证解析结果限于项目内。标签与缓存绑定已验证的真实文件身份，不能只靠会变的全局root重新解释相对路径，也不能把前端规范化当成授权。
4. **物理共享不等于视图共享。** A下两项目共享同一物理文件仍各自保有项目视图；B下即使同项目、同物理文件，不同Session也分别保有标签/滚动/选择状态。两种方案都不能仅凭磁盘路径跨工作集复用DOM。移除root、改主源、项目移除或数据源变化时先重验，失效标签标不可用并保留轻量记录，不静默映射到另一个root同名文件。
5. **历史差异与live文件分开。** 同文件不同轮、同轮不同冻结revision、当前文件和历史差异都不能按path单独去重。历史删除文件可继续查看已有合法差异；“查看当前文件”不存在时说明不可用，不把后来重建的同名文件当旧版本。

阶段1的“不改后端”是边界，不是可实现性结论。若现有接口无法稳定核验UI scope、实际解析文件和root变化后的对应关系，应停在阶段0提出独立合同，不用拼接path或共享缓存猜测身份。任何收窄或扩大现有路径访问规则均另行评估、批准，不能借本稿承诺已实现项目硬隔离或顺带重构路径安全。

## 5. 本轮改动事实：覆盖盘点与数据合同（新增，待确认）

### 5.1 当前工具可提供的证据和不足

[server.py](../server.py) 21868–21912行的`execute_write_file_tool`在普通文件分支返回path/diff/backupPath/replayed；同内容重放可返回空diff。27715–27734行`execute_propose_edit_tool`明确返回`applied=False`，只是建议。实际应用入口是27818行`execute_apply_edit_proposal`，核心在27737–27815行；应用结果包含path/diff/backupPath/applied/replayed，且校验内容hash及mtime。当前源码并非名为`execute_apply_edit_tool`的独立函数。

这些字段能作为盘点起点，但不等于已建立任务级可靠记录：受管记忆等特殊分支返回形态需单独盘点；backupPath可能为空，资源存在期也未由本方案确认。单工具diff不自动覆盖命令/脚本写文件，不自动提供完整before/after链、请求/子任务归属或重启后历史可用性。失败/拒绝的建议不能计为已应用，`replayed`不能再增加一次副作用；没有可靠应用证明时应标未知，而非仅凭“ok”或模型文字归因。

### 5.2 归属、汇总与冻结建议

- 以真实AgentRun和一次实际用户请求的执行关系作为归属证据；明确队列、steer、重试、恢复、子任务和独立后台任务分别如何加入。子任务必须有可核实父子关系，不能因同Session/同时段就合并；Goal跨多轮，未经定义不能把整个Goal算“一轮”。阶段0先冻结这套命名和归属，不由UI自行猜测。
- 每项事实至少需可核对的操作/工具身份、scope与受控文件身份、应用状态、重复回放关系、前后内容证据或其缺口。这里只列信息需求，不冻结sidecar键名/schema、保存位置、保留期或删除策略。
- 同轮同文件多次编辑，只有连续且可核实的首前→末后链才能给净diff；不得简单拼接unified diff或累加增删行数。链断裂、外部写入穿插、资源缺失或中间状态不明时只提供逐操作差异与明确缺口，不能伪造净差。
- 新增/修改/删除类别需文件存在性及操作证据；重命名必须有可靠关联证据，不能靠相似内容或路径猜测。同轮新增后删除等净零情况仍应保留可解释的操作事实，不与“没有发生副作用”混淆。
- 任务开始前已有dirty内容、其他任务和外部并发写入不归本轮。Git工作区diff不能单独证明Agent归属；非Git项目也应能显示受管文件工具已确认的改动，命令/脚本覆盖不足则标范围不完整。
- 成功、失败、取消和恢复都按已有执行事实记录副作用。模型终态文案不能证明文件是否改变；未知执行窗口需保留核对状态，不把丢响应当未写，也不把重复返回算两次。
- 本轮历史差异一旦确认冻结就以其revision阅读，不随当前文件轮询重算。历史无证据不回填编造；合法旧差异即使当前文件已删仍可查看；diff/备份/正文未保留时明确不可用。修正归属或补证据需新revision及原因，不能悄悄覆盖原审查结果。

### 5.3 必须独立批准的边界

若需AgentRun sidecar、新只读接口或持久副作用索引，属于新的数据/恢复合同，按STRICT另批。先确定字段与版本、来源/去重、截断/保留与清理、权限/路径、失败/重启恢复、旧数据读取及降级，再实现摘要和diff。UI整合推荐仍放`CODE-042`；文件改动事实/恢复若需新能力，建议设独立关联事项，但本轮**仅建议，不分配ID、不修改私有计划**。

## 6. 轻量UI持久化、旧键与回退

按推荐B，文件UI可使用版本化registry：scope→Session身份/代次（或独立draft）→标签描述、activeTabId、内部reuseTabId、paneOpen、创建顺序、模式、行号、滚动、图片缩放和review选中引用；projectId/root信息属于文件组织和上下文映射，不是授权凭据。若用户选择A，则UI归属维度改为project，不能在一份实现中混用。历史review仅保留合法记录的引用/选中项；差异事实来自单独批准的数据合同，不能把浏览器localStorage当持久审计账本。

- 不持久化正文、图片字节、PDF DOM、语法高亮HTML或任意服务端响应；每个已选工作集的标签数、序列化字节和view-state范围设确定上限，不能静默丢弃活动项。
- 保留`code-preview-width`作为既有全局宽度偏好，不因迁移重置。新多标签键名仅为实现候选，需版本与严格解析合同，不在评审稿中当成已经发布的格式。
- `code-preview-open/path`只在新记录缺失、当前scope/已选UI归属身份与API实际解析文件的对应关系全部验证成功时惰性导入一次。B仅导入当前已确认Session或独立draft，不广播到同项目全部会话。成功保存新记录后才允许更新或镜像旧键，镜像也只指向当前有效scope的活动文件；不全量扫描或迁入其他项目。
- 未知版本、损坏、过大、存储失败或不可验证旧值都保留原值，不覆盖“修复”、不删除用户状态；呈现该scope无可用预览或明确不可用。原稿“损坏时回退到旧单路径”收紧为：**只有旧路径也通过当前scope完整校验才可使用**，绝不能跨项目回退。
- UI版本回退只承诺有证据验证的旧单文件路径/宽度行为，不承诺旧构建具备项目隔离能力。不能安全证明时停止自动恢复，保留新旧记录；切回新版仍可核对。阶段2事实格式的降级另按STRICT合同，不能以清空凭据作为回退办法。
- 阶段1不删除原用户状态，不修改Session JSONL或后端协议；不新增迁移弹窗。手动清除浏览器状态后的空工作区沿既有规则降级，不恢复已被用户删除的UI数据。

## 7. 异步、焦点与资源管理

共享侧栏控制器应统一接收打开意图，避免文件树、消息链接和review各自管理正文。selectedWorkspaceIdentity在B为Session/draft身份及代次，A为project身份。建议加载身份至少含`scope + selectedWorkspaceIdentity + projectScope + viewKind + tab/reviewId + contentRevision + requestSeq + workspaceEpoch`；具体字段在阶段0冻结。

切换已选UI工作集/标签/视图时先记录轻量状态（B包括同项目切Session，A包括切project）、递增epoch、停止旧轮询并隐藏旧正文，再建立目标壳和活动身份。只有身份、revision、请求序列仍一致的响应能提交正文、mtime、错误、滚动或模式；关闭、替换浏览槽、快速切文件、跨scope和root移除均使旧请求失效。AbortController可节流，但不能代替提交时的身份复核。

仅活动live文件拥有既有刷新轮询；历史diff不轮询当前文件来改变冻结结果。后台标签、非当前会话/项目工作集和未展开review零预加载，不能一次恢复所有文件。任意时刻一个活动renderer/轮询槽，切出即释放图片监听、PDF iframe、Markdown/表格事件、resize帧、pointer capture及可能的Object URL；正文不能因多标签而长期多份缓存。

用户明确打开时才转焦点到对应视图，关闭返回原触发点；后台完成、自动刷新和失败提示不夺取焦点。loading/error/unavailable均必须属于当前对象，不能显示其他项目的标题或内容；失败只影响当前项，不清空其他工作区。B下后台同项目的其他Session也不能切换当前侧栏。
