# 项目级多标签预览工作区开发指导

> 状态：待开发方案（`CODE-042`）
> 方案确认日期：2026-08-24
> 适用范围：第一阶段单侧栏多标签预览
> 本文记录后续实现边界，不代表当前产品已经支持多标签。Codex 等产品只提供交互灵感，不构成内部实现、数据格式或兼容承诺。

## 1. 目标与第一阶段完成线

把当前右侧单文件预览升级为按项目隔离的多标签工作区，同时保持现有文件读取、安全路径、预览类型和双入口能力：

- 预览工作区绑定项目，不绑定会话；同项目内切换会话保留标签、活动标签和视图状态。
- 跨项目切换必须原子隔离，目标项目只看到自己的标签；旧项目的迟到请求、轮询或渲染不得写入目标项目。
- 第一阶段只有现有右侧预览栏和一条标签栏，不做左右分栏或独立窗口；任一时刻只渲染活动标签。
- 普通单击复用一个浏览标签；双击、Ctrl/中键或明确“在新标签打开”入口新建标签。
- 同一路径已经打开时，不论从哪个入口或用哪种打开动作，都只激活既有标签，不创建副本。
- 标签创建后在可见能力上地位相同：都可激活、关闭、重新加载和保留视图状态；界面不暴露“临时 / 固定”概念。

第一阶段完成不等于代码编辑器、多窗格 IDE 或系统窗口管理器。文件仍为只读预览，服务端 `/api/file` 与现有安全边界保持不变。

## 2. 当前实现证据

截至 2026-08-24，当前实现仍是单预览状态：

- `src/features/preview.js` 直接使用 `state.previewPath`、`previewContent`、`previewKind`、`previewMode`、`previewTable`、`previewImageScale` 和 `_previewMtime` 表示唯一活动文件。
- 文件树和最终回答中的本地文件链接都调用同一个 `loadFile`；这条共享路由已经统一文本、Markdown、CSV/TSV、图片、PDF、二进制降级和行号定位。
- `loadFile` 在请求完成后写入全局 `code-preview-open=1` 与 `code-preview-path=<path>`，然后替换唯一预览 DOM；`close` 清除这两个键和当前内容。
- `code-preview-width` 是全局宽度偏好；启动时先恢复宽度，在配置、Session 和项目根加载后再调用 `previewFeature.restore()` 恢复全局路径。
- 活动预览每 3 秒轮询一次当前 `previewPath`；切换文件会重用同一轮询槽。当前没有项目级标签身份、请求序列或每标签视图快照。
- Session 导航在目标 Session 带有 `cwd` 时调用 `saveProjectRoot(..., { syncSession: false })`，后者重新加载文件树和项目上下文；当前全局预览并不会随项目根建立独立命名空间。

这些事实说明第一阶段应扩展前端状态和恢复层，而不是新增第二条文件读取协议或在文件树、消息渲染器中分别实现标签逻辑。

## 3. 已确认的产品行为

### 3.1 项目与会话

- 项目是工作区隔离单位。能取得稳定 `projectId` 时以它作为主身份；未归属项目但有项目根的兼容场景，应使用规范化根路径生成明确的本地 fallback 身份，不能与其他项目混用。
- 同一项目中的任意 Session 共用该项目的预览标签；切换 Session 不关闭、不重排标签，也不把标签写入 Session JSONL。
- 切换到另一个项目时，先冻结并隐藏原项目的可见预览，再恢复目标项目工作区。目标项目恢复完成前不得继续显示原项目文件。
- 返回原项目时恢复该项目自己的标签、活动项和安全视图状态；恢复失败只影响对应标签，不得清空其他项目工作区。

### 3.2 打开规则

处理任何打开动作前，先用项目身份与规范化项目内路径查重：

1. 已存在：激活既有标签，并应用本次明确的行号定位；不新建、不重排其他标签。
2. 普通单击：若有有效的内部浏览复用槽，则原位替换其文件；否则创建一个标签并把它作为后续普通单击的复用目标。
3. 双击、Ctrl/中键或明确新建入口：创建新标签并激活。

“浏览复用槽”只能是打开路由内部的游标，不得成为可见标签类型、徽标、固定状态或不同关闭语义。显式新建的标签与其他标签使用同一 DOM、键盘、关闭和恢复规则；后续实现若无法在不暴露临时/固定概念的前提下保持普通单击复用，应停止并重新确认交互，而不是偷偷引入两类标签。

中键应阻止浏览器默认导航并走同源预览逻辑；Ctrl 与平台等价修饰键的最终支持范围需由双入口真实测试确认。文件树目录导航、`@` 插入、右键菜单和显式系统打开不随标签规则改变。

### 3.3 标签关闭与活动项

- 关闭非活动标签只移除该标签及其内存视图状态，不影响活动 DOM。
- 关闭活动标签时，优先激活同项目中最近访问的剩余标签；没有剩余标签时关闭预览栏并停止轮询。
- 关闭整个预览栏只改变该项目的“栏是否打开”状态，不应默认删除其标签；若产品实现希望“关闭栏即清空”，必须另行确认，第一阶段不得自行选择。
- 标签顺序第一阶段按创建顺序稳定保存；不加入拖拽排序、固定、分组或跨项目移动。

## 4. 建议状态模型

状态应集中在预览 feature 或其直接的纯状态辅助中，文件树和消息入口只提交统一打开意图：

```text
PreviewWorkspaceRegistry
  version
  activeProjectKey
  projects[projectKey]
    paneOpen
    activeTabId
    reuseTabId          # 仅内部路由游标，不是标签类型
    tabs[]
      id
      path              # 规范化后的项目内路径
      displayName
      mode              # rendered/source/table 等既有模式
      line
      scrollTop/scrollLeft
      imageScale
      updatedAtHint
```

约束：

- 不持久化文件正文、图片字节、PDF DOM、语法高亮 HTML 或服务端响应；激活时继续从 `/api/file` 获取受限内容。
- `path` 必须通过现有项目根安全校验；项目身份不能代替路径授权。
- `id` 只用于前端节点和请求身份，不能成为 Session、AgentRun 或服务端文件协议字段。
- 每项目标签数量与持久化字节应设置保守上限；超限策略应在实现阶段用确定性规则定义，不能静默丢弃活动标签。
- 状态解析失败时 fail-closed 到该项目无标签，并保留可回退的旧键；不能把损坏状态投影到其他项目。

## 5. 旧 localStorage 兼容、迁移与回退

当前三个键必须有明确兼容路径：

### `code-preview-width`

- 第一阶段继续作为全局界面宽度偏好使用，不必复制到每个项目。
- 新状态损坏或回退旧版本时仍能恢复同一宽度；不得因为多标签迁移重置用户宽度。

### `code-preview-open` 与 `code-preview-path`

- 新项目级状态不存在时，仅对启动时的当前项目尝试一次惰性导入：`open=1` 且路径通过当前项目安全校验时，创建一个活动标签；无效、越界或缺失路径不导入。
- 导入必须幂等；新状态已有有效项目记录时不得反复覆盖。
- 第一阶段 rollout 期间，活动项目与活动标签可继续镜像这两个旧键，使回退到旧构建时至少恢复一个活动预览；旧键不承担多标签事实源，也不能跨项目恢复错误路径。
- 新状态成功保存前不删除旧键。新状态损坏时不覆盖或“修复”旧值，安全回退到旧单路径读取或无预览。
- 推荐使用带版本的新 localStorage 文档，例如 `code-preview-workspaces-v1`；实际键名和序列化辅助可在实现时确定，但必须有 schema/version、大小上限和严格解析测试。

不新增迁移弹窗，不全量扫描项目，不写 Session JSONL，不要求服务端迁移。用户清除浏览器本地状态后的既有安全降级仍是空工作区。

## 6. 项目切换和异步竞态

项目切换必须采用先隔离、后加载、按身份提交的顺序：

1. 捕获原项目活动标签的轻量视图状态。
2. 递增全局 `workspaceEpoch`，停止原活动标签轮询，撤销仍持有的 pointer capture，并立即清空或隐藏预览正文。
3. 切换 `activeProjectKey`，只恢复目标项目标签壳与活动身份。
4. 为目标活动标签发起加载，携带 `projectKey + tabId + loadSeq + workspaceEpoch`。
5. 响应只有在四项身份仍匹配时才能提交 DOM、mtime、模式、滚动和错误状态；否则静默丢弃。

至少覆盖以下竞态：

- A 项目慢请求返回前切到 B 项目；A 响应不得出现在 B。
- 同项目快速点击两个文件；较旧响应不得覆盖较新活动标签。
- 加载中关闭或替换复用标签；响应不得复活已关闭身份。
- 自动刷新请求期间切标签、切项目或关闭栏；迟到结果不得重启动轮询或改写新活动项。
- 同路径从文件树和最终回答同时打开；只保留一个标签和一个可提交的活动响应。

可以使用 `AbortController` 减少无用请求，但 abort 不能替代身份核对；无法中止的请求仍必须由序列和项目身份丢弃。

## 7. 渲染和资源释放

- 标签栏可以保留多个轻量描述，但只有活动标签拥有文件正文 DOM、Markdown/表格渲染、图片节点、PDF iframe、语法高亮和 3 秒自动刷新。
- 切出活动标签时记录必要的轻量视图状态，然后销毁或替换重型 DOM；切回时重新走统一渲染链，不在后台维护隐藏的完整预览树。
- 每次活动身份变化先停止旧轮询，再启动新轮询；全局最多一个预览轮询器。
- 图片缩放、表格模式、Markdown 模式、代码行定位和滚动位置按标签保存；内容和 mtime 仍以服务端最新响应为准。
- PDF iframe、图片监听器、表格/Markdown 事件、resize animation frame、pointer capture 和临时 Object URL（如未来引入）必须在标签关闭、项目切换和 feature dispose 时释放。
- 大型文本继续沿用服务端前 1 MiB 与前端免高亮门槛；多标签不得把多个大型正文长期缓存到内存。
- inactive 标签不轮询、不触发网络、不写持久化；项目切换不能导致所有标签并发恢复。

## 8. 第一阶段明确排除

- 左右分栏、上下分栏、同文件多窗格或多活动渲染器。
- 独立系统窗口、拖出标签、跨窗口同步或 Explorer/默认程序生命周期管理。
- 可编辑文件、保存、dirty 状态、冲突合并、撤销历史或语言服务。
- 标签拖拽排序、固定/临时标签、标签组、跨项目移动、最近关闭列表。
- Session JSONL、AgentRun、Goal、项目服务端 schema 或 `/api/file` 协议变化。
- 后台预加载全部标签、完整大文件缓存、磁盘缓存或新的第三方依赖。

上述能力如后续需要，应拆成独立事项和验收，不能借第一阶段状态模型顺带实现。

## 9. 分阶段实施建议

### 阶段 A：纯状态与兼容层

- 建立项目工作区 registry、路径去重、复用/新建/关闭/激活纯状态规则。
- 实现版本化 localStorage 解析、旧键惰性导入、旧键镜像和损坏回退。
- 不接真实 DOM 前先用确定性测试闭合项目隔离、上限和幂等。

### 阶段 B：统一打开路由与标签栏

- 让文件树、搜索结果和最终回答本地链接提交相同的打开意图。
- 增加单侧栏标签壳、活动/关闭可访问性、普通单击复用和显式新建动作。
- 保留目录导航、右键、默认程序、行号和图片/PDF/二进制既有语义。

### 阶段 C：项目切换、恢复与资源闭环

- 接入 Session 导航和项目根切换的原子隔离点。
- 加入请求序列、轮询唯一性、重型 DOM 释放和视图状态恢复。
- 完成 reload、损坏状态、旧键回退、bundle/direct classic 与人工验收后再收口提交。

每个阶段都保持 `CODE-042` 同一稳定 ID；阶段 B/C 未验收前不得把事项写成完成。

## 10. 自动验证矩阵

### 纯状态与迁移

- 同项目同路径去重；不同项目同相对路径互不共享。
- 普通单击复用唯一内部槽；双击、Ctrl/中键、明确入口新建；已有路径一律激活。
- 关闭 active/inactive、最近访问回落、最后标签和栏开关规则确定。
- 旧 open/path 导入一次、宽度保留、双写回退、损坏/超限/越界状态 fail-closed。

### 异步与资源

- A→B 项目慢响应、同项目双请求、关闭中请求、轮询中切换的迟到结果全部丢弃。
- 任一时刻只有活动标签内容 DOM 和一个轮询器；inactive 标签零网络。
- 图片、PDF、Markdown、CSV/TSV、文本、大型截断文本、空文件、二进制和失败提示按既有路由投影。
- 标签/项目关闭后计时器、监听器、iframe、pointer capture 和临时资源清理。

### 集成与 H4

- 文件树、搜索结果、最终回答本地链接使用同一标签查重和打开规则。
- 同项目两 Session 切换保持；跨项目切换立即隔离；reload 后每项目恢复正确。
- bundle 与 direct classic 结果一致，页面无横向溢出，移动宽度下标签栏可操作。
- H4 使用临时数据根和受控文件，不产生模型请求、工具执行、真实系统窗口或意外网络。
- 相关前端模块、Node 语法、frontend build/freshness 和 `git diff --check` 通过。

## 11. 人工验收

在 Code Dev 与 direct classic 各执行一次：

1. 项目 A 普通单击三个文件，确认浏览标签复用；双击、Ctrl/中键和明确入口各新建一次，确认标签可独立切换、关闭且无“临时/固定”文案。
2. 从文件树和最终回答打开同一文件，确认只激活既有标签；行号链接仍定位正确。
3. 在项目 A 的两个会话间切换，确认标签、活动项、宽度和视图状态保留。
4. 切到项目 B，确认项目 A 内容立即消失且 B 只显示自己的标签；快速往返时无旧内容闪现或迟到覆盖。
5. 覆盖文本、Markdown、表格、图片、PDF、大型截断文本和二进制降级，确认只有活动标签渲染和刷新。
6. 刷新页面与重启本地服务，确认新状态恢复；再用旧键兼容样本验证单路径迁移和宽度不重置。
7. 在约 390px 宽度与明暗主题下检查标签可读、关闭按钮、键盘焦点、横向滚动和预览正文无页面级溢出。

## 12. 停止条件

实施中出现以下任一情况应停止并重新审批：

- 无法稳定取得项目身份，必须把标签重新绑定 Session 或允许跨项目共享。
- 需要修改 `/api/file`、项目/Session schema、消息 JSONL、AgentRun/Goal 协议或服务端持久化。
- 普通单击复用必须通过用户可见“临时/固定”两类标签才能实现。
- 无法保证跨项目切换先隔离、迟到响应不提交，或必须同时保留多个重型渲染器。
- 兼容迁移会删除旧键、不可逆改写用户状态或要求用户手工清空数据。
- 需要左右分栏、独立窗口、编辑保存、新依赖或第一阶段排除项。
- bundle/direct classic、旧会话/项目、图片/PDF/二进制安全路由出现不一致或回归。
